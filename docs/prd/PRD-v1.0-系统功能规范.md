## 1. 产品定位与边界

### 1.1 一句话定位

在离线的一体机上，按《在用曳引驱动电梯安全评估报告》JTE-09-R02-3.00 的规范，辅助检验人员完成电梯安全评估的现场录入、风险判定与报告签发。

### 1.2 目标用户

| 角色 | 使用场景 | 使用频率 |
| --- | --- | --- |
| 检验员 | 现场逐条录入评价结果，生成并导出报告 | 每次评估 |
| 系统管理员 | 开号、改密、重置口令、看日志、做备份、处理异常 | 低频但关键 |
| 审核员（建议新增） | 复核报告、退回或审定 | 每份报告 |
| 只读查阅人（可选） | 查看已归档报告 | 偶发 |

### 1.3 系统做什么

1. 账号、角色与权限：登录、改密、用户开户与停用、会话管理。
2. 评估作业：按模板录入 66 条评价结果，支持草稿、断点续录。
3. 风险判定：由知识图谱检索故障链，规则引擎 + 大模型产出风险评定值。
4. 报告签发：按模板生成报告，导出 PDF / Word，登记归档。
5. 报告管理：编号、检索、查看、重新导出、作废。
6. 系统管理：参数配置、图标与机构信息、审计日志、备份恢复、自检诊断。
7. 终端适配：一体机全屏、软键盘、屏幕旋转、开机自启与一键退出。

### 1.4 系统不做什么

1. 不做云端同步与多机联网（本期单机；若后续要多机，见 Q8）。
2. 不修改知识图谱内容与关系（图谱是既有资产，系统只读）。
3. 不做电梯实时数据采集（传感器、物联网接入不在范围）。
4. 不做财务、合同、检验收费等业务系统功能。
5. 不重新标定 FEM / LSN 等评估方法学参数。

### 1.5 运行环境事实（硬约束，需求必须迁就它们）

| 项 | 实测值 | 对需求的影响 |
| --- | --- | --- |
| 屏幕 | 物理 1200×1920，逻辑视口 600×960（竖）/ 960×600（横） | 页面按窄屏设计；不用横向滚动 |
| 浏览器内核 | WebKit2GTK 2.44.2（约 Safari 17.4） | 可用 ES2020，不可依赖更新的 API |
| 运行时 | Python 3.10.12，apt / pip 不可用 | 新依赖必须预置 aarch64 wheel |
| 网络 | 离线，无外网 | 所有资源本地化；不做在线校验 |
| 依赖服务 | Neo4j（7687）、RKLLM（8080）、FastAPI（8081） | 任一不可用都要有明确降级与提示 |
| 模型 | Qwen3.5-4B（板端实测） | 文档与界面中的模型名必须以此为准 |
| 系统时间 | RTC 不可信，开机会回到 2021-01-01 | 报告时间必须可信（见 FR-11.4） |

## 2. 术语

| 术语 | 含义 |
| --- | --- |
| 评价条目 | 模板中一行「项目编号 + 项目 + 评价内容与要求」，共 66 条 |
| 评价结果 | 三态取值：符合 / 不符合 / 无此项 |
| 不符合情形 | 选择"不符合"后勾选的具体原因，可多选，可自填"其他" |
| 风险评定值 | 严重程度、概率等级、风险类别三列，由系统计算得出 |
| 综合安全状况得分 G | 按附录A 公式计算，0～100 |
| 综合安全状况等级 | 一级 / 二级 / 三级 / 四级 |
| 报告状态 | 草稿 / 已生成 / 已归档 / 已作废（见 4.2） |
| 图谱条目 | Neo4j 中的检测项目节点（INS_*，共 41 条），与评价条目不是同一套编号 |

## 3. 角色与权限

### 3.1 角色定义

| 角色代码 | 名称 | 说明 |
| --- | --- | --- |
| admin | 系统管理员 | 全部权限，含用户管理、系统配置、备份恢复 |
| inspector | 检验员 | 录入、生成、导出、管理自己的草稿与报告 |
| reviewer | 审核员（建议 P1） | 查看全部报告、审定或退回，不能改用户与系统配置 |
| viewer | 只读（可选 P2） | 只读已归档报告 |

### 3.2 权限矩阵

| 功能 | admin | inspector | reviewer | viewer |
| --- | --- | --- | --- | --- |
| 登录、改自己的口令 | 是 | 是 | 是 | 是 |
| 录入 / 保存草稿 | 是 | 是 | 否 | 否 |
| 生成报告 | 是 | 是 | 否 | 否 |
| 导出 PDF / Word | 是 | 是 | 是 | 否 |
| 查看自己的报告 | 是 | 是 | 是 | 否 |
| 查看他人报告 | 是 | 否 | 是 | 是（仅已归档） |
| 删除 / 作废自己的报告 | 是 | 是 | 否 | 否 |
| 审核（通过 / 退回） | 是 | 否 | 是 | 否 |
| 用户管理（开户 / 停用 / 重置口令） | 是 | 否 | 否 | 否 |
| 系统配置、日志、备份恢复 | 是 | 否 | 否 | 否 |
| 退出系统（返回桌面） | 是 | 否（可配置） | 否 | 否 |

### 3.3 权限设计原则

1. **默认拒绝**：接口默认要求登录；需要管理员的路由逐一显式标注。
2. **数据按人隔离**：报告、草稿的查询一律带用户条件，不存在"猜 id 读别人数据"的路径。
3. **不能锁死自己**：不允许停用、降级或删除最后一个可用管理员。
4. **改密与停用即失效**：改密或停用后，该用户已签发的会话立即作废。
5. **特权操作留痕**：用户管理、配置变更、备份恢复、报告作废全部写审计日志（见 FR-9.3）。

## 4. 业务流程

### 4.1 端到端主流程

```text
登录 ──► 新建评估 ──► 填四个必填项
                          │
                          ▼
              逐条录入 66 条评价结果（可随时保存草稿）
                          │
                    ┌─────┴─────┐
                    ▼           ▼
                 漏填校验     全部通过
                    │           │
          列出漏填并可跳转      ▼
                          生成报告（图谱 + 规则 + 大模型）
                                │
                                ▼
                     报告预览（正文 / 评价结果表 / 附页 / 附录A）
                                │
                     ┌──────────┴──────────┐
                     ▼                     ▼
                 导出 PDF / Word        登记归档（编号 + 状态）
```

### 4.2 报告状态机

```text
草稿 ──生成──► 已生成 ──导出并归档──► 已归档 ──作废──► 已作废
  ▲              │
  └──── 继续修改 ─┘（生成后允许回到录入页改，改完重新生成，版本号 +1）
```

| 状态 | 含义 | 允许的操作 |
| --- | --- | --- |
| 草稿 | 只存填写内容，没有编号、不计入统计 | 继续录入、删除 |
| 已生成 | 已算出风险评定值与 G，编号已分配 | 预览、导出、修改后重新生成、删除 |
| 已归档 | 已导出并登记（含文件校验和） | 重新导出、查看、作废 |
| 已作废 | 号码保留不复用，记录仍在库中 | 仅查看 |

审核流程（P1，配置开关，默认关闭）：已生成 → 待审核 → 已审定 / 已退回。

### 4.3 降级与异常

| 异常 | 系统行为 |
| --- | --- |
| Neo4j 不可用 | 报告生成被拒绝，提示"知识图谱服务未就绪"，录入与草稿不受影响 |
| RKLLM 不可用 | 仍生成报告：风险评定值走规则引擎，叙述性文字用图谱摘要替代，并在报告与界面标注"未使用大模型生成" |
| LibreOffice 不可用 | 导出失败并给出可读原因（已实现），提供"仅预览"兜底 |
| 导出目录不可写 | 导出前预检并提示，不产生半成品文件 |
| 磁盘空间不足 | 录入与生成前检查剩余空间，低于阈值（建议 200 MB）时告警 |

## 5. 功能需求

每条需求的写法固定为：**现状 → 需求 → 业务规则 → 验收**。
「现状」一栏是本次开发前代码库的真实状态，用来判断工作量与优先级。

### FR-1 认证与会话

**现状**：后端已实现登录、退出、查当前用户、改密（PBKDF2-HMAC-SHA256 加盐），会话令牌有效期 7 天；前端只有登录页，**没有改密入口**，也没有失败锁定与会话超时提示。

**需求**

1. 登录：用户名 + 口令；失败提示不区分"用户不存在"与"口令错误"。
2. 注销：清除本地令牌，回到登录页。
3. 修改口令：入口放在侧边栏用户区；必须输入原口令；成功后强制重新登录。
4. 首次登录强制改密：预置管理员与新建用户首次登录必须改密后才能使用。
5. 口令策略：长度 ≥ 8，同时含字母与数字，不得与用户名相同，不得与前 3 次口令重复。
6. 登录失败锁定：连续 5 次失败锁定 10 分钟（可配置），锁定期间提示剩余时间。
7. 会话超时：默认空闲 8 小时自动注销（现为 168 小时，需调小）；到期前 5 分钟提示。
8. 会话管理（P1）：管理员可查看在线会话并强制下线。

**业务规则**

- 口令只以加盐哈希形式落库，任何接口不得回传哈希与盐。
- 改密、停用、重置口令后，该用户已签发的全部会话立即失效。
- 令牌失效的接口统一返回 401，前端统一跳登录页，不弹系统框。

**验收**

1. 口令错误时前端提示统一文案，不含"用户不存在"字样。
2. 改密成功后，原令牌立刻失效，页面回到登录页。
3. 连续 5 次失败后，即使口令正确也拒绝登录，直到锁定结束。
4. 空闲超过阈值自动注销并提示；未操作不会误判为超时。
5. 新用户首次登录被拦到改密页，改密前无法进入录入页。

### FR-2 用户管理

**现状**：后端接口齐全（列表、新增、修改、删除，含"最后一个管理员"保护与改密/停用后踢下线）；**前端完全没有页面**。这是当前最大的功能缺口之一。

**需求**

1. 用户列表：用户名、姓名、角色、状态、创建时间、最后登录时间；支持按状态与角色筛选。
2. 新增用户：用户名唯一、初始口令、角色、是否要求首次改密。
3. 编辑用户：改姓名、改角色、启用/停用。
4. 重置口令：管理员代设新口令，并强制该用户下线。
5. 删除用户：二次确认；已有历史报告的用户默认改为"停用"而不是物理删除（保留可追溯性）。
6. 批量导入（P1）：按 CSV 批量开户检验员。
7. 自我保护：不能停用、降级或删除当前登录账号；不能删除最后一个可用管理员。

**业务规则**

- 用户名一经创建不可修改（避免历史报告责任人不明确）。
- 停用用户保留全部历史数据，仅禁止登录。
- 所有用户管理动作写审计日志，含操作者、目标用户、变更前后值。

**验收**

1. 非管理员账号访问用户管理接口返回 403，且界面上看不到该入口。
2. 停用某用户后，该用户正在使用的会话立即失效。
3. 尝试停用最后一个管理员时被拒绝并给出原因。
4. 管理员不能删除自己。
5. 每次开户/停用/重置口令，审计日志都能查到对应记录。

### FR-3 评估作业（录入）

**现状**：已实现。抬头表四项必填、66 条条目连续排列、三态选择、不符合情形多选 + 其他自填、漏填清单与跳转定位、草稿保存、左侧可折叠导航、悬浮岛计数。

**需求**

1. 抬头信息表按模板：**委托单位名称、使用单位名称、设备类别、产品编号**四项必填，其余填空默认为"/"。
2. 条目表严格按模板顺序连续排列 66 条，不按系统分组。
3. 评价结果三态：符合 / 不符合 / 无此项；选"不符合"时展开情形多选与"其他（自行填写）"。
4. 漏填校验：列出具体缺项（字段名与条目编号），可点击跳转并高亮、聚焦。
5. 草稿：自动保存（输入防抖）+ 手动保存；支持继续上次录入。
6. 清空/恢复默认：一键清空本次填写，二次确认。
7. 术语统一：全站不得出现"合格/不合格"，一律"符合/不符合"。

**业务规则**

- 模板条目原文中的 a) b) 1) 等排列标记不显示（属排版标记，非内容）。
- 漏填判定至少覆盖：四个必填项为空；条目未选评价结果；选了"不符合"但未勾选任何情形且未填"其他"。
- 条目文本与顺序来自 `backend/app/data/jte_items.json`（由模板 docx 自动抽取），不手工硬编码在页面里。

**验收**

1. 四个必填项缺失时提交被拦截，清单逐条可点击并跳转到位。
2. 生成前统计数字（共/已评/不符合/未填）与实际一致。
3. 刷新页面或重新登录后，草稿内容可恢复。
4. 页面不出现"合格/不合格"字样。

### FR-4 报告生成与预览

**现状**：预览已实现正文页、评价结果表、附页、附录A；风险评定值目前是占位算法（按序号循环），需按 Q6 定稿。

**需求**

1. 报告结构按模板：封面、报告正文、评价结果表（含风险评定值三列）、附页、附录A。
2. 风险评定值必须由系统给出：不符合项经知识图谱检索 + 规则判定，得到严重程度、概率等级、风险类别。
3. 附页列出全部不符合项，列序固定：序号、项目编号、存在风险、风险类别、降低风险措施。
4. 附录A 的综合得分 G 与等级由公式计算，禁止大模型参与定级。
5. 生成报告需记录溯源信息：使用的图谱链路、规则命中情况、是否调用大模型。
6. 报告版本：每次重新生成版本号 +1，历史版本可查。

**业务规则**

- 定级公式（模板附录A）：
  `G = 100 × Σv_i / (2n)`，当所有 `v_i ≠ 0`；存在 `v_i = 0` 或 `Σv_i < 0` 时 `G = 0`。
  风险类别取值：Ⅰ类 = 0、Ⅱ类 = -1、Ⅲ类 = 2。等级：G≥90 一级、75≤G<90 二级、60≤G<75 三级、G<60 四级。
- 大模型只负责叙述性文字，不得改写编号、数值、风险类别。
- 生成过程必须可中断、可重试；失败不得产生半份报告。

**验收**

1. 评价结果表中"风险评定值"三列均有值，且与图谱/规则结果一致、可复现。
2. 附页行数与"不符合"条数一致。
3. 手工按公式复算 G 与等级，与系统输出一致。
4. 断开 RKLLM 后仍能生成报告，且界面与报告中明确标注未使用大模型。

### FR-5 导出与交付

**现状**：已实现 HTML → LibreOffice 无头转换 → PDF / Word；失败提示可读；导出按钮已移到悬浮岛；导出结果卡片含"打开文件""打开所在文件夹""关闭"。

**需求**

1. 文件名规范：`{报告编号}_{使用单位}_{yyyyMMdd}.pdf` / `.docx`。
2. 导出目录固定为板端 `/home/user/导出`；按日期建子目录（P1）。
3. 每次导出写审计日志，并在报告记录里保存文件路径、大小、SHA-256。
4. 导出前预检：LibreOffice 可用、目录可写、磁盘剩余空间充足。
5. 导出中按钮进入忙碌态，禁止重复提交。
6. 导出完成后展示结果卡片并自动滚动到可见位置。

**业务规则**

- 导出目录之外的文件不能被"打开文件"接口访问（服务端白名单，已实现）。
- 导出失败必须给出可定位原因，不得透出内部异常堆栈。
- 同一份报告重复导出不覆盖旧文件，文件名追加序号。

**验收**

1. 导出的 PDF 与 Word 用 Word / PDF 阅读器打开，版式与模板一致。
2. 目录不可写时，导出立刻失败且提示可读。
3. 导出成功后点击"打开文件"能直接打开刚生成的文件。
4. 导出记录可在审计日志与报告详情中查到。

### FR-6 报告管理

**现状**：后端有报告历史接口（按用户隔离、每人保留 50 条上限），**前端没有历史/归档页面**。

**需求**

1. 报告列表：编号、状态、使用单位、设备编号、评估日期、创建人、导出情况。
2. 检索与筛选：按编号、使用单位、日期区间、状态、创建人（管理员/审核员可看全部）。
3. 详情：查看报告内容、溯源信息（图谱链路、规则、大模型输出）、导出文件记录。
4. 操作：重新导出、继续编辑（回到录入）、复制为新建、作废、删除（受权限矩阵约束）。
5. 统计（P2）：按月份/检验员统计报告数量与不符合项分布。

**业务规则**

- 报告编号规则：`GDSEI-JTE-{年份}-{4 位流水}`，流水按年重置，作废号码不复用。
- 编号在"已生成"时分配，草稿没有编号。
- 删除与作废必须二次确认，并写审计日志。
- 保留上限由"每人 50 条"改为按时间与状态策略（见 7.3）。

**验收**

1. 检验员只能看到自己的报告；管理员能看到全部。
2. 按编号检索能精确定位到唯一记录。
3. 作废后号码不再分配给新报告。
4. 点"继续编辑"能带着原数据回到录入页。

### FR-7 知识图谱与大模型

**现状**：Neo4j 存 302 节点 / 392 关系（板端实测，与 CSV 一致）；RKLLM 提供 Qwen3.5-4B 流式推理；后端已有健康探针 `/api/health/ready`、图谱查询与流式生成接口。

**需求**

1. 图谱只读：系统不得写图谱，只按检测项与异常状态检索故障链（状态 → 现象 → 风险 → 措施 → 条款）。
2. 大模型只做叙述：输入来自图谱事实与用户录入，输出回填叙述字段。
3. 调用留痕：每次生成记录使用的条目、图谱链路条数、是否命中模型、耗时。
4. 降级：模型不可用时用图谱摘要 + 规则结果出报告，并在界面与报告上标注。
5. 超时与重试：单次模型调用超时上限可配置（默认 600s），失败自动重试 1 次。

**验收**

1. 停掉 Neo4j 后，报告生成被拒并给出明确原因，录入与草稿不受影响。
2. 停掉 RKLLM 后仍能出报告，且标注"未使用大模型生成"。
3. 生成失败不留半份报告、不占用报告编号。

### FR-8 模板与条目库管理

**现状**：`tools/gen_jte_items.py` 从模板 docx 自动抽取 66 条到 `backend/app/data/jte_items.json`，版本靠仓库管理。

**需求**

1. 条目库版本化：每次抽取记录来源文件与哈希，界面"关于"中可查当前条目库版本。
2. 模板变更可重建：模板换版时重新抽取并跑差异核对，条目增删要有提示。
3. 评估依据与仪器等固定文本可配置，不写死在代码里。
4. 历史报告锁定模板版本：报告记录里保存生成时使用的条目库版本，便于追溯。

**验收**

1. 重新抽取后条目数、编号、顺序与模板一致。
2. "关于"页面展示条目库版本与哈希。

### FR-9 系统管理与审计

**现状**：参数全靠 `backend/.env`（Neo4j 地址、会话时长、历史条数、预置管理员），**没有配置界面，也没有审计日志表**。

**需求**

1. 参数配置界面（管理员）：机构名称与 logo、导出目录、会话时长、历史保留策略、是否允许退出系统、LLM 超时与开关。
2. 配置落库并保留变更历史（谁在什么时候把哪个值从什么改成了什么）。
3. 审计日志：登录成功/失败、注销、改密、用户增删改停、重置口令、报告生成、导出、删除、作废、配置变更、备份与恢复、退出系统、手工校时。
4. 日志查询：按时间、操作者、事件类型、结果筛选；支持导出 CSV。
5. 日志防篡改：只追加，不提供界面删除入口；保留期按策略轮转归档。

**验收**

1. 每类特权操作都能在日志中查到操作者、时间、目标与结果。
2. 配置修改后立即生效（需要重启的项要明确提示）。
3. 非管理员看不到系统管理入口，接口返回 403。

### FR-10 数据备份与恢复

**现状**：无。这是"上现场前必须做"的项之一。

**需求**

1. 一键备份：打包 SQLite 业务库、导出目录、配置快照、条目库版本，输出到指定目录（默认 `/userdata/backup/{yyyyMMdd-HHmmss}/`）。
2. 备份清单：生成 `manifest.json`，含文件列表与 SHA-256。
3. 恢复：管理员操作 + 二次确认 + 恢复前自动备份现状；恢复后校验并提示重启。
4. 保留策略：本地保留最近 N 份备份（默认 10），超出按时间清理。
5. 支持外置 U 盘路径（插拔后路径可见）。

**验收**

1. 备份产物可在另一台机器上完整恢复（业务库 + 报告文件 + 配置）。
2. 恢复过程中断电不产生半损坏的数据库（先写临时文件再原子替换）。
3. 备份失败（空间不足、路径不可写）时给出可读原因。

### FR-11 终端与运行环境

**现状**：GTK3 + WebKit2GTK 全屏壳、开机自启、单实例、输入法中英切换、屏幕旋转自适应均已实现。

**需求**

1. 开机自检：三个服务（Neo4j / RKLLM / FastAPI）就绪后才进主界面，未就绪时显示进度与原因。
2. 退出系统：按权限与配置决定是否显示；退出前提示保存草稿。
3. 中文输入：保留中/英切换按钮，并在输入框聚焦时自动切换。
4. 屏幕方向：竖屏 600×960 与横屏 960×600 都要完整可用，无横向滚动。
5. 时间可信（**重点**）：RTC 不可信，开机时间为 2021-01-01。要求：
   - 开机时以"业务库/文件的最新时间"或管理员手工设置为准；
   - 报告时间不得早于上一次记录时间，出现回退时提示校时；
   - 校时动作写审计日志。
6. 服务自愈：`elevator-app.service` 监管，异常退出自动重启并记录。
7. 一键诊断：脚本输出各服务状态、磁盘、时间偏移、依赖可用性与数据库完整性。

**验收**

1. 开机到可登录不超过 60 秒（含依赖就绪等待），过程中有明确进度提示。
2. 断电重启后业务库与草稿不丢。
3. 时间回退时给出提示，且报告时间不出现倒退。
4. 诊断脚本一次运行输出全部检查项结论。

### FR-12 说明与帮助

**现状**：无。

**需求**

1. 关于页：系统版本、模型名称（Qwen3.5-4B）、条目库版本、图谱规模、依赖服务版本。
2. 操作指引：现场常见问题（漏填、导出失败、图谱未就绪、时间不对）的处理说明。
3. 首次使用引导（P2）：一页图文说明录入流程。

**验收**：关于页信息与实际运行环境一致（模型名、条目数、节点数）。

## 6. 非功能需求（NFR）

### 6.1 性能

| 指标 | 目标 |
| --- | --- |
| 条目目录加载 | < 300 ms（本地 JSON） |
| 录入交互响应 | < 50 ms（纯本地状态） |
| 草稿保存 | 防抖 800 ms，写入 < 200 ms |
| 图谱查询 | < 1 s |
| 大模型首字 | < 5 s（流式） |
| 报告生成全量 | < 90 s（66 条、含模型） |
| 导出 PDF / Word | P95 < 5 s |
| 冷启动到登录页 | < 15 s（服务已就绪） |

### 6.2 可靠性

1. 任一依赖服务不可用，系统都要给出可读原因与可执行的下一步，不允许白屏或英文系统弹窗。
2. 数据库操作使用短连接 + 事务，写入失败回滚。
3. 断电不损坏数据：恢复/备份使用临时文件 + 原子替换。
4. 报告生成、导出均可中断与重试，不留半成品。

### 6.3 安全

1. 口令加盐哈希（PBKDF2-HMAC-SHA256，迭代 ≥ 120000），不回传、不打印。
2. 会话令牌随机生成，可撤销，改密/停用即失效。
3. 越权防护：所有业务数据访问带 user_id 条件。
4. 文件访问白名单：仅允许导出目录内的文件被"打开"接口访问。
5. 服务监听收紧到本机回环（现可能对局域网开放），跨域策略收紧到同源。
6. 目录与文件权限：数据目录 750、`.env` 600（现为 777 / 666）。
7. 审计日志覆盖全部特权操作。

### 6.4 可维护与可运维

1. 数据库结构变更走版本化迁移（`schema_version` 表），禁止手工改表。
2. 业务库与导出目录放到持久分区 `/userdata`，每日备份。
3. 结构化日志 + 轮转，保留最近 30 天。
4. 一键诊断脚本与版本信息接口。

### 6.5 兼容与适配

1. WebKit2GTK 2.44（约 Safari 17.4）：ES2020 语法，不依赖新 API。
2. 竖屏 600×960 与横屏 960×600 均可用，无横向滚动；触控目标不小于 40×40 逻辑像素。
3. 字体缺失时回退到系统无衬线字体，报告正文固定仿宋_GB2312（缺失时回退宋体）。

### 6.6 合规

1. 报告输出必须与 JTE-09-R02-3.00 模板一致，可直接签发。
2. 报告数据留存可追溯：编号、创建人、生成时间、模板版本、图谱链路、导出文件校验和。
3. 数据删除须有权限、二次确认与日志。

## 8. 接口需求（面向接口设计）

本节只定"要有哪些接口、口径是什么"，具体字段在《接口设计》中定稿。

### 8.1 通用约定

1. 风格：REST，路径统一 `/api/**`，请求与响应均为 JSON（导出下载除外）。
2. 鉴权：`Authorization: Bearer <token>`；失效统一返回 401。
3. 响应体：成功 `{success:true, ...}`；失败 `{success:false, detail:"可读中文原因"}`。
4. 列表：统一分页参数 `page` / `size`，返回 `total` 与 `items`。
5. 时间：ISO 8601 本地时间字符串，例如 `2026-10-12T14:30:00`。
6. 破坏性操作（删除、作废、恢复、重置口令）必须带二次确认标记，且写审计日志。

### 8.2 接口分组清单

| 分组 | 接口 | 现状 |
| --- | --- | --- |
| 认证 | POST `/api/auth/login`、POST `/api/auth/logout`、GET `/api/auth/me`、POST `/api/auth/change-password` | 已有 |
| 账号 | GET/POST `/api/auth/users`、PATCH/DELETE `/api/auth/users/{id}` | 已有（无前端） |
| 账号（新增） | GET `/api/auth/sessions`、DELETE `/api/auth/sessions/{id}`、POST `/api/auth/users/import` | 待建 |
| 条目与依据 | GET `/api/report/jte-items`、GET `/api/report/inspection-items`、GET `/api/report/assessment-basis` | 已有 |
| 生成 | POST `/api/report/generate`、POST `/api/report/generate-stream` | 已有 |
| 报告管理 | GET `/api/reports`、GET `/api/reports/{id}`、POST `/api/reports/{id}/void`、POST `/api/reports/{id}/regenerate`、DELETE `/api/reports/{id}` | 待建（现有为 `/api/history`） |
| 草稿 | GET/PUT/DELETE `/api/draft` | 已有 |
| 导出 | POST `/api/export`（格式 pdf/docx）、GET `/api/export/file?name=`、POST `/api/export/open` | 已有 |
| 系统 | GET/PUT `/api/system/config`、GET `/api/system/audit`、GET `/api/system/info`、GET `/api/system/diagnose` | 待建 |
| 运维 | POST `/api/system/backup`、POST `/api/system/restore` | 待建 |
| 终端 | POST `/api/kiosk/exit`、GET `/api/kiosk/status`、POST `/api/ime/toggle` | 已有 |

### 8.3 错误码约定

| 状态码 | 语义 | 例子 |
| --- | --- | --- |
| 400 | 参数或业务规则不满足 | 原口令不正确 |
| 401 | 未登录或令牌过期 | 未登录或登录已过期 |
| 403 | 已登录但无权限 | 需要管理员权限 |
| 404 | 目标不存在 | 记录不存在 |
| 409 | 冲突 | 用户名已存在、报告编号重复 |
| 422 | 字段校验失败 | 口令强度不足 |
| 503 | 依赖未就绪 | 图谱服务未就绪、导出目录不可用 |
| 500 | 其他服务端异常 | 只给可读原因，不透出堆栈 |

### 8.4 安全约定

1. 所有业务接口默认要求登录；`/api/health` 与登录接口例外。
2. 报告、草稿的读写必须带当前用户条件；管理员/审核员的跨用户查询走独立接口并单独授权。
3. 文件下载只允许导出目录内的文件，路径需做规范化后比对白名单。

- 正文为白卡（`--c-panel`）承载，页面标题居中黑体。
- 底部悬浮岛常显：共 / 已评 / 不符合 / 未填 计数 + 保存草稿 + 导出按钮（主按钮样式）。
- 窄屏（≤900px）适配：抬头表为"标签带 + 取值"两段式；条目表把一行拆成「编号+项目 / 评价内容与要求 / 评价结果」三段，保留表格观感；三态按钮内边距 10px 以保证触控目标。
- 报告预览：A4 等比缩放，不重排；竖屏也完整可见。

### 9.3 文案与术语

1. 评价结果只用：符合 / 不符合 / 无此项。
2. 不出现"合格/不合格"。
3. 标题为"在用曳引驱动电梯安全评估报告"，不叫"电梯基本信息"。
4. 禁止营销式文案（"一键…""智能…""极致…"）。

### 9.4 禁用项

1. 暖色（米 / 褐 / 黄）一律不得出现；语义红 `#c5343e` 与其浅底除外。
2. 不用 emoji 作图标；不用渐变铺底与玻璃拟态。
3. 一屏不超过三种强调色。
4. 直角风格（本版已否决）。
5. 每次改版不得改动登录页与启动页的既有样式（已固化为回归项）。

## 10. 验收标准

### 10.1 自动化验收（已具备，必须保持全绿）

| 脚本 | 覆盖 |
| --- | --- |
| `tools/acceptance/http_acceptance.py` | 21 项：健康检查、鉴权边界、登录、条目目录、导出失败可读性、文件白名单 |
| `tools/acceptance/ui_acceptance.js` | 两个逻辑视口（600×960 / 960×600）：登录页还原、主题令牌、暖色残留、行底色规则、字段名字体、条款编号清理、窄屏三态按钮溢出、侧边栏折叠、漏填拦截与跳转、报告页数、内容校验、导出、悬浮岛按钮 |
| `backend/tests/test_export_service.py` | 导出错误处理回归 |
| 样式比对（建议入库） | 设计稿 vs 应用的计算样式逐项比对 |

### 10.2 板端端到端验收

1. 开机自检通过后进入主界面，登录。
2. 新建评估，填四个必填项，对若干条目选择三种评价结果，"不符合"多选情形并自填其他。
3. 故意漏填提交，清单可点击跳转并补全。
4. 生成报告，核对正文、评价结果表、附页、附录A；手工复算 G 与等级。
5. 导出 PDF / Word，用阅读器打开核对版式。
6. 报告列表中找到该记录，重新导出、查看溯源信息、作废。
7. 管理员：开户、停用、重置口令、查看审计日志、执行备份与恢复演练。
8. 断电重启，确认草稿、报告、配置与时间均正常。

### 10.3 需求级验收

本文档每条 FR 末尾的"验收"条目都必须能落到可执行的检查（脚本或明确的手工步骤）。没有验收方式的需求不进入开发。
