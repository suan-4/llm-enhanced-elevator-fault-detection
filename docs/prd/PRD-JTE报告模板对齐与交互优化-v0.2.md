## 1. 背景与问题

系统功能已跑通，但离"可正式交付"还有四类差距。

**一、输出报告与机构模板不一致。** 现在导出的报告是系统自拟结构，而实际交付物必须逐字段匹配《在用曳引驱动电梯安全评估报告》JTE-09-R02-3.00。模板含封面、报告正文、评价结果表、附页、附录A、附图六个部分，其中附页、附录A 的表头与计算规则此前系统完全没有实现。

**二、录入交互不符合现场习惯。**

- 术语用"合格／不合格"，机构规范用"符合／不符合"。
- "不符合"的原因只能从系统预设状态里选，现场遇到的实际情况超出预设时无处填写。
- 漏填被拦截后，只提示"有未填写项"，不说是哪几项，也不跳转，用户要在几十个条目里自己找。
- 导出按钮在报告预览上方，用户每次导出都要把长页面翻回顶部。
- 导出成功后提示自动消失，没有可点击的入口打开刚生成的文件。

**三、界面观感与行业系统不符。** 现有页面偏"通用 Web 应用"风格，与特种设备检验检测行业系统的实际形态差距明显。

**四、版本事实来源不清。** 电脑上存在外层与嵌套两套项目副本，配置与文档互相矛盾（例如模型名、端口）。任何改动都必须以板端 EM-R16 实际运行版本为基准。

## 2. 目标与非目标

### 2.1 目标

1. 导出的 PDF／Word 与 JTE-09-R02-3.00 逐字段一致，可直接签发。
2. 录入界面按现场检验流程组织，术语、选项、校验行为符合机构规范。
3. 界面视觉向机构自有系统靠拢，去掉"生成式"观感。
4. 不破坏板端现有运行能力与数据。

### 2.2 非目标（本轮不做）

- 不修改知识图谱内容与关系。
- 不重新标定 FEM／LSN 算法参数。
- 不重写前端框架，不做响应式改版。
- 不调整既有 API 路径与数据结构。

## 3. 需求清单

### R1 术语与评价结果选项

**描述**

- 全站术语由"合格／不合格"改为"符合／不符合"。
- 评价结果保留三种取值：符合、不符合、无此项。
- 选择"不符合"时，除系统按知识图谱给出的情形清单外，新增"其他"选项，允许用户自由填写文字。
- 情形清单支持多选。

**验收标准**

1. 界面与导出报告中不再出现"合格／不合格"字样。
2. "不符合"情形可勾选多项，勾选后"其他"展开文本框。
3. 勾选的已有情形与"其他"文字共同写入报告"存在风险"列。

### R2 漏填校验可定位

**描述** 提交时若存在漏填，除拦截外还必须：

- 列出具体漏填项（项目编号 + 项目名称 + 缺失原因）。
- 每条可点击，点击后自动滚动到该条目并高亮。

**验收标准**

1. 提示区明确显示"以下 N 项未填写"。
2. 点击任一条目，页面平滑滚动至对应行并短暂高亮。
3. 点击后聚焦到该条目首个可编辑控件。
4. 漏填判定至少覆盖：未选评价结果；选了"不符合"但未勾选任何情形且未填"其他"。

### R3 导出按钮位置

**描述** PDF／Word 导出按钮移到报告预览内容的下方。

**验收标准** 报告预览区域内不再出现导出按钮；导出区位于报告末页之后，滚动到底部即可看到。

### R4 导出后跳转

**描述** 导出完成后给出带操作按钮的结果提示，而不只是一次性 toast。

**验收标准**

1. 提示常驻，显示文件名、大小、保存路径。
2. 提供"打开文件"按钮，直接打开刚导出的文件。
3. 提供"打开所在文件夹"按钮与"关闭"按钮。
4. 提示出现后自动滚动到可见位置。

### R5 按 JTE-09-R02-3.00 生成报告

**描述** 报告结构、栏目、默认值、计算规则全部按模板执行。详见第 4、5 节。

**验收标准**

1. 报告含封面、正文、评价结果表、附页、附录A 五个必需部分。
2. 封面与正文的四个必填项取自用户输入。
3. 除必填项外，模板中其余填空默认为"/"。
4. 评价结果表含"风险评定值"三列，数值由系统给出。
5. 附页列出全部不符合项，含风险类别与降低风险措施。
6. 附录A 的得分与等级由公式计算，不由大模型编造。

### R6 界面规范化

**描述** 按第 6 节的规范重做视觉与布局，使其与机构自有系统一致。

**验收标准** 符合 6.4 节全部禁用项检查；主色、字体、边框、圆角与 6.2 节设计令牌一致。

## 4. 模板解析结论

以下为直接解析 `JTE-09-R02-3.00 在用曳引驱动电梯安全评估报告(2).docx`（104 段、12 张表）得到的事实，不是推断。

### 4.1 文档结构

| 顺序 | 部分 | 说明 |
|---|---|---|
| 1 | 封面 | 质量体系文件编号、标题、5 行信息表、注意事项、机构联系方式 |
| 2 | 报告正文 | 标题 + 21 行基本信息表（含评估结论、整机建议、签署栏） |
| 3 | 评价结果表 | 6 张续表，列为：项目编号、项目、评价内容与要求、评价结果、风险评定值 |
| 4 | 附页 | 序号、项目编号、存在风险、风险类别、降低风险措施 |
| 5 | 附录A | 风险类别分值表、综合得分公式、等级判定表 |
| 6 | 附图 | 序号、现场照片、说明 |

### 4.2 填空规则

- 报告正文页保留四个必填项：**委托单位名称、使用单位名称、设备类别、产品编号**。
- 其余栏目默认为"/"，语义是"可填可不填"，不是"无此项"。
- 封面信息表含 **设备品种**（不是设备类别）与评估日期，需单独确认填法。

### 4.3 评价结果取值

模板示例行明确写为：

```text
符合、不符合（文字描述）、无此项
```

即三态取值，且"不符合"必须带文字描述。这与 R1 一致。

### 4.4 风险评定值

评价结果表右侧为三列合并表头"风险评定值"：

| 严重程度 | 概率等级 | 风险类别 |
|---|---|---|

模板示例行将这三列标注为"自动"，即由系统计算，不由人工填写。

### 4.5 附页与降低风险措施

附页固定列序为：序号、项目编号、存在风险、风险类别、降低风险措施。模板给出两条范例措施文本：

| 风险类别 | 降低风险措施（模板原文） |
|---|---|
| Ⅰ类 | 建议结合技术及经济可行性，加装或改进安全保护装置（措施）来消除或降低风险。 |
| Ⅱ类 | 应采用修理、调整、更换等措施消除或降低风险。 |

附页下方注："出厂时符合当时标准，但缺少或不符合现行标准所规定的安全保护装置（措施）而产生的风险。"

### 4.6 附录A 计算规则

分值表（表A.1）：

| 风险类别 | Ⅰ | Ⅱ | Ⅲ |
|---|---|---|---|
| 值 | 0 | -1 | 2 |

注：Ⅰ类风险为一票否决项。

综合安全状况得分 G（原文为 Word 公式对象，已解析还原）：

```text
G = 100 × ( Σ v_i ) / (2n)     当所有 v_i ≠ 0
G = 0                          当存在 v_i = 0，或 Σ v_i < 0
```

其中 v_i 为第 i 个风险情节的风险类别取值，n 为风险情节总数。

等级判定（表A.2）：

| G | G≥90 | 75≤G<90 | 60≤G<75 | G<60 |
|---|---|---|---|---|
| 综合安全状况等级 | 一级 | 二级 | 三级 | 四级 |

注意：因 Ⅰ类对应取值 0，"一票否决"在公式中自然实现——只要存在 Ⅰ类风险，G 即为 0，等级为四级。

### 4.7 排版规格

| 项 | 实测值 |
|---|---|
| 正文字体 | 仿宋_GB2312 |
| 正文主力字号 | 10.5pt（五号） |
| 标题字号 | 22pt / 26pt |
| 行距 | 1.1 倍（表格区）、1.5～2.0 倍（说明段） |
| 表格线 | 单实线，黑色 |

报告预览必须复刻以上规格，不能沿用界面字体。

## 5. 数据流与算法落点

### 5.1 端到端链路

```text
用户在条目上选择评价结果
        │
        ├─ 符合 / 无此项 ──────────────► 直接写入评价结果表
        │
        └─ 不符合 + 情形（可多选）+ 其他文字
                    │
                    ▼
        知识图谱按检测项检索故障链
        （状态 → 现象 → 风险 → 措施 → 条款）
                    │
                    ▼
        规则引擎 + 大模型产出风险评定值
        （严重程度 / 概率等级 / 风险类别）
                    │
                    ▼
        附页：存在风险 + 风险类别 + 降低风险措施
                    │
                    ▼
        附录A 公式计算 G 与综合安全状况等级
                    │
                    ▼
        导出 PDF / Word（套 JTE 模板）
```

### 5.2 职责划分（关键）

| 环节 | 由谁负责 | 原因 |
|---|---|---|
| 故障链、风险、措施 | 知识图谱（Neo4j） | 事实必须可溯源 |
| 严重程度、概率等级、风险类别 | 规则 + 大模型，以规则优先 | 需可复现，不能每次生成不同结果 |
| 综合得分 G 与等级 | 纯公式计算 | 附录A 有明确定义，不允许模型发挥 |
| 报告文字表述 | 大模型 | 语言组织 |

**硬规则**：G 与等级必须由公式计算得出。大模型只负责叙述，不得参与定级。

### 5.3 风险评定值的产生（待确认，建议方案）

模板要求三列，但未给出取值体系。建议方案：

- **严重程度**：取知识图谱状态节点的 `severity`（现有 1～5 级）。
- **概率等级**：由状态出现条件推导，建议 A～E 五档，A 最易发生。
- **风险类别**：由严重程度与概率等级二维矩阵映射到 Ⅰ／Ⅱ／Ⅲ 类。

矩阵映射表需与特检院确认后固化到配置，不写死在代码里。

### 6.3 布局规则

- 顶部固定 48px 标题栏，左侧机构标识 + 系统名，右侧视图切换与账号。
- 作业模式为左右两栏：左侧项目导航（各分组未评数量），右侧条目表。
- 条目表使用真实表格网格，不用卡片堆叠。
- 底部固定操作条，常显已评／不符合／漏填计数。
- 报告模式为主体纸面预览，A4 宽度居中。

### 6.4 禁用项（针对现有"生成式"观感）

以下特征一律不得出现在界面中：

1. 大圆角卡片（半径 > 4px）与卡片投影堆叠。
2. 渐变背景、彩色光晕、玻璃拟态。
3. Emoji 作为图标（✅ ⚠️ 📄 等）。
4. 大面积高饱和色块铺底。
5. 营销式文案（"一键…"、"智能…"、"极致…"）。
6. 居中大标题 + 副标题的落地页式排版。
7. 无意义的动效与骨架屏动画。
8. 超过三种强调色同时出现在一屏。

## 7. 页面结构

### 7.1 作业模式（评估录入）

```text
┌ 顶部栏 ── 机构标识 / 系统名 / 报告编号 / 视图切换 / 账号 ─────────┐
├ 校验提示条（有漏填时出现，可点击逐条跳转）─────────────────────┤
│  以下 N 项未填写： 委托单位名称 · 1.9 限速器 · 2.1 …            │
├──────────────────────────────────────────────────────────────┤
│  在用曳引驱动电梯安全评估报告        ← 居中大标题，与文档一致    │
│  ┌────────────────────────────────────────────────────────┐  │
│  │ 委托单位名称 [输入]*  使用单位名称 [输入]*                │  │
│  │ 安装地点 /            设备类别 [输入]*                   │  │
│  │ 型号 /                产品编号 [输入]*                   │  │
│  │ …其余栏目默认「/」，可改                                │  │
│  └────────────────────────────────────────────────────────┘  │
│  ┌────────────────────────────────────────────────────────┐  │
│  │ 项目编号 │ 项目 │ 评价内容与要求 │ 评价结果             │  │
│  │ 1.7      │ …    │ …              │ 符合/不符合/无此项    │  │
│  │ 1.9      │ …    │ …              │ …                     │  │
│  │ …（按模板顺序连续排列，共 66 项，不按系统分组）            │  │
│  └────────────────────────────────────────────────────────┘  │
├──────────────────────────────────────────────────────────────┤
└ 底部操作条 ── 共 66 / 已评 N / 不符合 N / 未填 N ── 保存 生成报告 ┘

要点：

1. **首屏就是报告抬头**，标题为「在用曳引驱动电梯安全评估报告」，不叫「电梯基本信息」。
2. **没有左侧项目导航**，条目按模板顺序一条道排到底。
3. **输入层不出现「风险评定值」列**。该列在生成报告后才随文档一并出现。
4. 未选评价结果的条目、以及选了「不符合」但未填情形的条目，都会进入漏填清单。
```

### 7.2 报告模式（预览）

按模板顺序渲染，一页一屏宽：

1. 报告正文页（四个必填项取自用户输入，其余为"/"）
2. 评价结果表（含风险评定值三列）
3. 附页（不符合项汇总）
4. 附录A（分值表、公式、等级表）
5. 可选：附图页

### 7.3 导出区

位于报告预览内容**下方**（R3）。导出后展示结果卡片（R4），含文件名、大小、路径与三个按钮。

## 8. 待确认问题

以下问题会实质影响实现方式，需在开发前定稿。

| 编号 | 问题 | 影响 |
|---|---|---|
| Q1 | "无此项"是否保留？用户本次只提到"符合／不符合／其他"，但模板示例行含"无此项" | 决定数据模型与报告取值 |
| Q2 | 条目清单以哪套为准？模板条目编号为 1.7／1.9／…／18.4（GB/T 42615-2023 体系），现有知识图谱为 41 条 INS_* 编号 | 决定是否需要建立"模板条目 ↔ 图谱条目"映射表，这是最大的工作量项 |
| Q3 | 封面的"设备品种"是否也按四必填规则处理？封面用的是设备品种，正文用的是设备类别 | 决定两个页面字段绑定是否一致 |
| Q4 | 严重程度、概率等级、风险类别的取值体系与映射矩阵 | 决定风险评定值能否自动产出 |

## 9. 端到端验收

在板端 EM-R16 上完整走一遍：

1. 登录，新开一份评估，填四个必填项。
2. 对若干条目选择"符合"、"不符合（多选 + 其他）"、"无此项"。
3. 故意漏填后提交 → 出现漏填清单 → 点击逐项跳转并补全。
4. 生成报告 → 预览结构与 JTE 模板一致。
5. 核对：四个必填项正确、其余为"/"、风险评定值三列有值、附页列出全部不符合项、附录A 得分与等级符合公式。
6. 滚到底部导出 PDF 与 Word → 出现结果卡片 → 点击"打开文件"能打开。
7. 导出文件用 Word／PDF 阅读器打开，版式与模板一致。
