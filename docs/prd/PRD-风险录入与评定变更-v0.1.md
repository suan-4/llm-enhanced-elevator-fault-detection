# 风险录入与评定变更需求

版本：v0.1。日期：2026-10-15。状态：待评审。

本稿补充《PRD-v1.0-系统功能规范.md》的 FR-3、FR-4、FR-7、FR-8。
目标是把专家提供的两份资料用于风险选择、确定性评定和措施生成。先确认本稿及待定规则，再设计接口和数据存储并实施。审核数据不直接进入运行系统。

- 综合计分 n 按实际参与评价的项目数：符合、不符合计入，无此项排除。同项目选择多个风险只计一次，项目类别取最严重者。
- 三条具体差异以评价表“不符合”样例为准：12.1:05 → 1/C/Ⅰ类；16.1:32 → 2/B/Ⅰ类；16.6:13 → 2/D/Ⅱ类。仅覆盖这三条，保留总表原始类别、措施及双方出处，不修改来源 DOCX。
- 附页同项目统一显示项目最终类别，各条风险和对应措施仍分别保留。
- 全部为无此项时 n=0，不计算满分，不分配正式编号；保留草稿并明确提示没有可评价项目。
- 本次沿用现有接口与数据表，实施更换风险选项及生成算法的小范围变更，不执行此前更大范围的 v2 接口/快照方案。

下文 Q1/Q2 及附页列义中的旧待定说明仅保留为评审历史，不再作为当前阻塞项；当前实现和验收状态见《风险材料接入-本次实施与验收》。

## 2 已确认业务规则

### R1 风险与评价项目关联

按项目编号展示该项目对应的风险。选“不符合”后可以多选具体风险，也可以填写“其他”。评价结果仍为符合、不符合、无此项。用户无需在初始输入层填写风险评定值。

### R2 同项目风险类别汇总

用户明确：同一个项目最终只有一个风险类别；存在多个风险时，以最严重的类别为准，Ⅰ类 > Ⅱ类 > Ⅲ类。

汇总作用于本次实际选择并确认的风险，不是该项目风险库中所有可能风险。没有风险或有风险尚未完成分类时，不凭空补一个类别。

每条风险原有类别和降低风险措施完整保留，不能因为项目汇总只取一类而丢弃其他风险及措施。类别汇总本身不能唯一确定严重程度和概率等级。

### R3 原文和系统推断可区分

总表中的风险、类别、措施和评价文档的样例原样留存。用户原文、模型匹配建议、确认结果分别记录。模型辅助自然语言理解和措施解析，正式数值与定级按经确认的规则计算。

## 3 本稿提出的交互与处理规则

本节是待审核的具体方案，不表示用户已经确认全部细节。

### FR-R1 不符合录入

1. 保留现有白色和蓝青色、圆角、登录页样式、连续 66 项布局，不引入新的项目侧栏。
2. 将当前从要求条款拆出来的候选情形，逐步替换为审核通过的专家风险选项。展示风险原文，允许多选；长文本可展开。
3. “其他”可与已有风险同时使用，输入内容完整保存。模型给出候选匹配及措施依据，检验员确认后进入正式评定。
4. 选择“不符合”但没有选择风险、也没有有效文字描述时，提示具体项目并定位。
5. 切换为符合或无此项时，旧风险信息暂存以便切回恢复，但不参与当前评定；再次保存和刷新仍保留切换状态。界面须清楚提示哪些内容当前不参与评定。
6. 自由描述未匹配、存在歧义时标为待确认，不强行给出类别；允许保存草稿，正式生成规则见 FR-R4。

### FR-R2 风险清单审核

1. 逐条审核总表语义，不按风险类别单独决定是否进入不符合选项。
2. 本轮逐条阅读 39 条Ⅲ类记录后，建议将它们标为正常/符合描述，保留作知识和对照，不放入不符合选项。该建议待业务审核；审核前不删除原文、不自动发布。
3. 三条非Ⅲ类差异如下。保留总表风险类别与评价样例类别两个来源，不作静默覆盖：

| 项目 | 具体风险 | 总表类别 | 该项目不符合样例 |
| --- | --- | --- | --- |
| 12.1 钢丝绳绳径减小 | 多根绳径减小差异明显，其中一根接近或达到限值，造成受力不均 | Ⅱ类 | 1C／Ⅰ类 |
| 16.1 控制柜 | 散热通道堵塞，元件温升增加，可能造成控制故障 | Ⅱ类 | 2B／Ⅰ类 |
| 16.6 安全开关 | 安全开关被短接，危险状态不能通过安全回路阻止运行 | Ⅰ类 | 2D／Ⅱ类 |

4. 按 R2，选中总表已确认风险时，项目类别取所选风险中的最严重类别。上述差异使样例的严重程度/概率组合不能直接照搬；处理办法列入 Q1。

### FR-R3 措施处理

1. 对已选择风险，先取总表对应措施，记录其来源。
2. 模型可以解析、整理多条措施，但原文保留；不得遗漏关键条件、参数及停用要求。生成内容与原始措施并列可核对，由检验员确认采用内容。
3. 表1的通用措施与总表的具体措施分别保存，通用描述不得覆盖具体措施。
4. 模型不可用时，现成风险选项和来源措施继续可用。仅当所有必要评定均已按正式规则确定时，才可无模型生成正式报告；未完成分类的自由描述继续保存为草稿。

### FR-R4 评定及计分

1. 风险矩阵按照原文完整保存：严重程度 1～4，概率等级 A～F，共 24 个组合。
2. 66 项符合与不符合样例作为标准参考及回归校验资料。当前资料不是大量真实现场标注数据；本次不安排模型微调，也不承诺模型自动达到评定准确率。
3. 项目最终类别采用 R2。严重程度、概率等级采用经确认的规则；不得由最终类别反推一个任意组合，也不得显示与矩阵矛盾的三元组。
4. 旧 PRD 已记载附录A公式及等级阈值，保留待核对；不得因本轮资料接入自行发明另一套公式。模板原文定义 n 为“进行评价的风险情节的总数”；风险情节如何对应项目汇总，以及符合、无此项和空集合处理仍须确认。
5. 正式生成前完成漏填检查、自由描述确认和评定一致性检查。尚有未解决项时允许保存草稿，提供具体项目位置，不伪装为已完成正式评定。
6. 正式规则获确认后替换当前演示循环分配，未确认前不把演示值标作专家正式评定。本稿不直接修改现有运行行为。

### FR-R5 报告与历史数据

1. 正文每个项目显示唯一的最终风险类别，并按正式规则填写严重程度和概率等级。
2. 附页保留每条确认风险及对应措施。建议一条风险一行，列为序号、项目编号、存在风险、该条风险类别、降低风险措施；同项目可多行。此列级含义须在最终审核时固定。
3. 本需求将旧 FR-4“附页行数与不符合条数一致”的验收改为“附页覆盖全部确认风险，无重复或遗漏”；项目计数与风险条数分别展示含义，不混用。
4. 预览、Word、PDF使用同一份生成结果和措施内容，导出时不重新请求模型改写。继续按 JTE 模板排版，不加标题背景色。
5. 草稿保存所有选择、原文、候选匹配和确认状态。历史报告锁定当次风险原文、类别、措施和规则版本；更新知识库不自动改变历史报告。
6. 接口及存储设计在 PRD 确认后进行。优先评估现有 JSON 和快照能否承载；本稿不预先承诺“不改接口/不改数据库”，也不先增加多张表。

## 5 验收场景

| 场景 | 预期 |
| --- | --- |
| 同项目选Ⅱ类、Ⅰ类、Ⅱ类风险 | 项目类别为Ⅰ类，三条风险及其措施均保留 |
| 库中存在Ⅰ类风险，本次只选Ⅱ类 | 项目类别为Ⅱ类，不受未选风险影响 |
| 同项目选多条同类别风险 | 项目仍只输出一个类别；具体计分次数依据Q2，不擅自按风险条数重复扣分 |
| 输入自由描述且候选匹配错误 | 可拒绝建议并修改；不自动写入错误的正式类别 |
| 模型不可用 | 已确认规则和来源措施可用；未分类文字可保存，生成提示准确 |
| 类别与样例严重程度/概率组合冲突 | 明确列出待确认项目，不显示矛盾三元组 |
| 切换结果、刷新或恢复草稿 | 当前结果、风险及暂存状态完整恢复，停用风险不参与计算 |
| 一项目多风险导出 | 正文一项、附页保留全部风险；预览、PDF、Word一致 |
| 12.4 断丝要求 | 阈值表的类型、数值和注释不丢失 |
| 更新风险清单 | 已生成历史报告的原文、措施和结果不被静默修改 |
