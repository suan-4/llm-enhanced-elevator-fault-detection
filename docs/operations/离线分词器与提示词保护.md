# 离线分词器与提示词保护

本说明仅供已批准的候选准备与验证，不是正式部署授权。不要直接把候选覆盖到`/home/ubuntu/elevator`。

## 准备与校准

在联网准备电脑安装`backend/requirements.txt`和`backend/tokenizer-requirements.txt`所列依赖；下载分词资源：

```powershell
.venv\Scripts\python.exe tools/prepare_tokenizer.py
# 如确需代理，只对这一条命令加 --proxy http://127.0.0.1:7890
adb forward tcp:18080 tcp:8080
.venv\Scripts\python.exe tools/calibrate_tokenizer.py --output backend/data/tokenizers/calibration-新批次
```

准备工具固定官方revision和SHA256，只取tokenizer.json/LICENSE，不下载权重、不伪造校准；已有哈希不符文件拒绝覆盖。校准工具只向正在运行的模型发合成请求，七组均真实完成、模型ID及差值符合要求后才写calibration.json。每组数值先落observations.jsonl，失败不写成功profile。不要以单元测试里的玩具profile当部署校准。

运行时只读本机文件、不访问HuggingFace。缺少依赖、资产或有效校准会明确拒绝模型调用；概况按已定PRD降级，自然语言匹配则保留草稿并要求重试/选择已知风险。历史报告不会自动重跑。

## RK3588离线依赖

准备包必须匹配Python3.10/aarch64。下载ARM64轮子时不能仅依赖Windows跨平台pip的环境标记：huggingface-hub还需要`hf-xet`。本次完整清单及哈希在验收制品`offline-wheels-manifest.json`，已在Ubuntu22.04板端从本地轮子安装成功。

示例（在新建的候选release内，不能对系统或正式目录直接安装）：

```bash
python3 -m pip install --no-index --find-links ./wheels --target ./runtime -r backend/tokenizer-requirements.txt
# 仅候选进程 PYTHONPATH 指向该 runtime；不要全局覆盖正式依赖。
```

分词文件12,807,982字节。模型仓库与两份资产哈希见`backend/app/data/tokenizer-source.json`，Apache-2.0许可证随资产包保留。依赖引擎固定0.22.1；transitive轮子逐个哈希留存，正式升级需重新锁定与复测。Git不带运行时文件，部署包必须显式带齐它们，不能只拉源码就声称模型可用。

## 候选配置

显式注入以下环境（路径换成经检查的新候选目录）：

```text
RKLLM_SERVER_URL=http://127.0.0.1:8080/v1/chat/completions
RKLLM_CONTEXT_TOKENS=4096
RKLLM_MAX_NEW_TOKENS=512
RKLLM_TEMPLATE_RESERVE_TOKENS=128
RKLLM_MODEL_ID=Qwen3.5-4B_W8A8_RK3588
RKLLM_TOKENIZER_PATH=data/tokenizers/qwen3.5-4b/tokenizer.json
RKLLM_CALIBRATION_PATH=data/tokenizers/qwen3.5-4b/calibration.json
```

相对路径按backend/解析；tokenizer和profile必须随候选部署到以上位置。库、恢复文件、导出、备份均指向新release内部，不复用正式路径；API仅监听回环独立端口。改配置/资产后只重启候选API，复用已有模型进程。模型/模板/原生运行时变更必须重新校准；不能把128误当精确固定模板token数。

## 复测

```powershell
# 必须是新release的专用测试库。此工具在登录/写入前核对健康接口中的精确库身份。
$env:ELEVATOR_BENCH_PASSWORD='仅用于合成测试账号的口令'
.venv\Scripts\python.exe tools/acceptance/prompt_guard_acceptance.py --base http://127.0.0.1:18084 --expected-db /userdata/releases/新批次/benchmark/performance-benchmark.db --output backend/data/新批次结果
```

工具会创建测试报告，禁止传正式库/正式账号。浏览器脚本`tools/acceptance/prompt_guard_browser.js`目前固定本次候选目录，换批次必须同步精确检查目标，不能删除隔离检查。它通过Playwright CLI `run-code --filename`执行，避免Windows命令行损坏多行JS引号。

本次源码、风险规则和模板保持可追踪；正式发布另外确认。候选通过后仍需实际板端WebKit、触屏和导出回归，不能用电脑Chromium代替现场签收。正式旧报告不自动迁移新状态，缺失字段显示“模型参与状态未记录”。
