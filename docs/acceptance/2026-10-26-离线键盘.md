# 离线触摸键盘验收（2026-10-26）

## 交付范围

已实现并更新开发板：常见平板 QWERTY、数字/符号、中英文、拼音候选、单字手写候选、离线短句语音。密码只允许键盘；整数/小数字段遵守原表单限制。语音先预览，再由用户明确点击“填入文字”，填入后可继续编辑，不自动保存录音或生成报告。

不修改风险评定、报告导出和账号数据，不修改登录品牌样式。普通电脑默认保留物理键盘，可手动打开应用输入面板。

## 开发板实测

同一候选产物在独立数据库服务验证；浏览器拼音请求使用真实板端引擎，语音传输竞态使用受控响应，真实语音模型另行实测，不能将两者混为端到端人声验收。

| 项目 | 结果 |
| --- | --- |
| 拼音 `zhidongqi` | 候选及选择得到“制动器”；完整回放请求839ms |
| 官方中文音频 | “开放时间早上9点至下午5点。” |
| 语音耗时 | 5.592秒音频，总耗时7334ms，包含每次模型加载，不是纯解码时间 |
| 麦克风捕获 | 400ms得到10674字节PCM，证明采集通路存在，不代表人声质量通过 |
| 取消录音 | 进程停止、临时音频目录消失 |
| 原生 WebKit | 键盘/手写/语音面板均能显示切换，手写笔画识别返回候选；未选择字符，未改业务字段 |
| GNOME旧软键盘 | 面板打开时D-Bus State返回false，未重复弹出 |

尚需现场确认：真人说话的拾音清晰度、噪声环境识别率；当前板端为横屏1920×1200/缩放2，竖屏仅完成对应逻辑视口浏览器测试。原生自动操作截图仍可见桌面左侧Dock覆盖第一列，这是桌面覆盖层而非第二个键盘；未擅自改桌面全局设置，需要现场触摸确认或另行处理。不将这些未测项写成全部验收通过。
