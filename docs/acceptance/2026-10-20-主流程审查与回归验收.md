## 尚未通过的验收条件

1. **最终模板版本未确定**：保留的 Word 样例 65 项，系统 66 项。差异见前一日模板核对记录。原微信临时文件失效，需要最终模板；不自行增删或替换项目。

3. **导出与报告记录没有绑定**：`POST /api/report/export` 仍收页面 HTML，没有报告 ID/版本或结果摘要校验；导出成功也没有调用已有 `report_repo.mark_exported`。因此“导出成功”目前不代表数据库已归档，服务端也无法核对 HTML 是否来自当前已生成结果。需在模板导出设计中明确快照来源、过期结果拒绝、文件记录及归档事务；不在本次局部修复中临时增加另一套协议。
4. **正式与候选部署存在差异**：本次分词保护、概况策略及本轮修复验证的是隔离候选，未发布到正式服务，不能把候选成功当成正式版本已具备这些能力。
5. **监听边界待运维收口**：实际业务 API 为 `127.0.0.1:8081`；模型端口 `8080`、ADB `5555` 仍监听 `0.0.0.0`。是否能被外部设备访问还取决于网卡和防火墙，本轮没有验证；也没有擅自修改调试通道或系统服务。
6. 本轮没有进行真实屏幕软键盘、拔电、磁盘满、完整恢复覆盖、MS Word 逐页视觉比对或多样本模型准确率验收。

## 同日补充：按开发流程与系统化调试追踪导出契约

本次补查使用 `software-development-lifecycle` 核对 PRD FR-5、接口设计 §3.6、数据库状态机；使用 `systematic-debugging` 从“没有归档记录”反向追踪调用链并做最小复现。

### 根因与可复现证据

实际链路为：

`web/src/utils/export.ts` 收集页面 HTML → `api/export.py` 接收正文 → `export_service` 转换并发布文件 → 返回成功。

链路没有读取报告记录。请求模型不声明 `report_id`，传入该字段也被忽略；`report_repo.mark_exported()` 只有定义，没有业务调用；导出接口没有写 `report_export` 审计。

`tools/acceptance/export_contract_probe.py` 使用真实 FastAPI 路由、临时 SQLite、真实账号会话和报告状态，仅把文档转换器换成记录调用的替身。没有接触正式数据库、没有生成真实导出文件。

| 场景 | 既有契约应有的行为 | 实际结果 |
| --- | --- | --- |
| 不传报告 ID | 在转换前拒绝 | HTTP 200，调用转换器 |
| 报告 ID 不存在 | 在转换前拒绝 | HTTP 200，调用转换器 |
| 已生成后又修改，传旧版本 | 拒绝旧结果 | HTTP 200，调用转换器 |
| 已作废报告 | 拒绝正式导出 | HTTP 200，调用转换器 |
| 正常已生成报告返回成功 | 文件登记、归档时间、已归档状态和审计可查 | 状态仍 generated，exported_at 为空，文件记录和导出审计均为 0 |

调用者提供的 HTML 在五个场景中都直接进入转换器。结论是**导出接口未实现报告绑定及状态约束**，不是数据库没有表，也不是转换器偶发失败。

该检查明确返回失败（退出码 1、`contract_passed=false`），不计入上一节 144 项后端回归或 75 项 HTTP 验收的通过数。它补出了原验收脚本缺少的契约覆盖，不能以旧脚本通过掩盖此缺口。

证据：[导出契约复现结果](data/2026-10-20-regression/export-contract-probe.json)。

### 最小修复范围建议（尚未实施）

1. 沿用现有导出路径，按已设计的报告 ID 获取服务端已生成数据；客户端不再提供正文、风险类别、得分或措施。补充版本/结果快照校验，防止同一输入重新生成后仍导出旧预览。
2. 只允许已生成且评定完整的报告、或已归档报告重新导出；草稿、过期结果、作废报告、未知 ID 在转换前拒绝。此次补查不引入新角色、新表或审批流程。
3. 渲染与转换期间不占用数据库写锁；完成后在短事务里重新核对状态和结果快照。报告期间被修改或作废时不能归档旧输出。
4. 用现有 `report.files_json` 登记文件名、格式、路径、大小、SHA-256、时间及对应结果标识，追加而不是覆盖其他格式记录；同一事务更新归档状态与写审计。文件发布和数据库提交之间的失败须有清理/恢复策略，不能声称文件系统与 SQLite 天然构成一个原子事务。
5. 原 Word 模板回填和 PDF 转换共用同一份已验证数据快照。模板不匹配或转换失败时不登记“成功”，也不能静默退回旧 HTML 通道。

开始实现前还需收敛两个已有条件：最终模板的 65/66 项版本差异，以及设计文件中的历史矛盾。接口设计中“已归档可先重新生成”和“导出时可分配编号”与数据库状态机/当前实现不一致；应沿用目前“生成时编号、归档后只读，修改则复制为新建”的已有行为进行文档核对，不能在接线时悄悄改变业务规则。
