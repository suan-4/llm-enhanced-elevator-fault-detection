# AI 推荐速度优化记录

日期：2026-10-29　范围：/api/kg/recommend

## 1. 改动

1. 规则快路径：
   - 只有一个候选 → 直接选；
   - 候选部件名与项目/现场描述有唯一最长公共子串 → 直接选；
   - 无候选 → 直接 none；
   - 候选打平或没有部件直接命中 → 才调用 4B。
2. 短 T2 提示词：
   - 只选一条；
   - 候选只给 component/system/90 字 summary；
   - query 压到 300 字；
   - 输出限制为 path_id + 20 字 reason；
   - max_tokens=96。
3. 进程内缓存：
   - key = item_no + item_name + reasons + candidates；
   - TTL 1 小时；
   - 重复进入/刷新直接命中。
4. 前端按需推荐：
   - 页面打开时所有项只跑规则快路径（fast_only），不调用模型；
   - 规则无法判断的项显示「AI 推荐」按钮，点击才调用模型；
   - 页面打开不再有任何模型请求等待。

板端 fast_only 实测：

    4.5  0.71s，无规则 → 显示 AI 推荐按钮
    8.3  0.10s，规则命中
    12.1 0.13s，无规则 → 显示 AI 推荐按钮

## 2. 板端实测

| 项目 | 优化前 | 优化后 | 说明 |
|---|---:|---:|---|
| 8.3 接地 | ~17s | **0.13s** | 部件名直接命中 |
| 4.5 编码器 | 17–26s | 16.7s | 三个编码器候选打平，走模型 |
| 13.7 轿架 | 17–26s | 14.8s | 两个轿架候选打平，走模型 |
| 12.1 钢丝绳 | 17–26s | 16.8s | 走模型 |
| 重复请求 8.3/4.5/13.7 | 17–26s | **0.11–0.13s** | 缓存命中 |

结论：

- 可唯一部件匹配的项已经秒出；
- 其余项仍受 4B 推理限制，缩短 prompt 后约快 10–20%；
- 缓存让页面刷新/重复进入不再等模型。

## 3. 批量推荐（已接入）

- 新接口：POST /api/kg/recommend/batch；
- 一次最多 3 项，规则可判的项直接返回，其余拼成一个模型请求；
- 前端头部按钮「AI 推荐剩余 N 项」。

板端实测（4.5 + 13.7 + 12.1，三项都需模型）：

    批量：41.9s
    逐项：约 15 + 15 + 16 = 46s

三项至少省约 4s；四项以上收益更明显，但受 4B 长 prompt 限制，暂不放开到更多项。

## 4. 下一步可选

1. 对“候选打平”的项增加更稳的规则（不能用分数硬选，4.3 会误选）；
2. 前端默认只自动推荐前 2–3 项，其余按需点击；
3. 批量推荐 2–3 项，比较总耗时；
4. 用人工确认日志训练一个轻量重排器，替代大部分 T2 模型调用。
