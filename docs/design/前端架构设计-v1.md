# 前端架构设计 v1

电梯智能安全评估系统 —— 由单文件原生 JS 迁移到 Vue 3 工程

| 项目 | 内容 |
|---|---|
| 版本 | v1 |
| 日期 | 2026-10-12 |
| 状态 | 待评审 |
| 前置决策 | 框架选定方案 A：Vue 3 + TypeScript + Vite + Pinia + Vue Router + 自研组件 |

---

## 1. 现状与目标

### 1.1 现状

前端目前是一个 `index.html`（88 KB）加一个 `marked.min.js`，没有框架、没有构建步骤、没有 `package.json`。

- 全部逻辑集中在约 100 个函数中，模块边界不存在。
- 报告模板（附页、附录A、评价结果表）以 JS 字符串拼接硬编码。
- 条目数据写死在前端文件里。
- 尺寸按 1240px 宽设计，未适配竖屏逻辑视口。

### 1.2 目标

1. 迁移到 Vue 3 + TypeScript 工程，组件化、类型化、可测试。
2. 把「模板」「数据」「业务规则」三层拆开，各自可独立修改。
3. 适配板端真实视口：竖屏 600×960、横屏 960×600。
4. 保持 API 路径与返回结构不变，板端服务零改动（除静态挂载）。
5. 一期完成后可直接上板运行并验收。

### 1.3 硬约束（实测）

| 项 | 值 | 影响 |
|---|---|---|
| WebKit2GTK | 2.44.2（≈ Safari 17.4） | 支持 ES2020+、ES Module；Vue 3 可直接用，无需降级 |
| GTK | 3.24.33 | 仅影响原生外壳，不影响前端 |
| 板端 Python | 3.10.12 | 后端改动需兼容 |
| 物理屏 | 1200×1920 竖屏 | 逻辑视口 600×960（竖）/ 960×600（横） |
| 板端网络 | 完全离线 | 只能在电脑上构建，产物推送到板端 |
| 部署方式 | adb push | 构建产物需纳入 `push.bat` 流程 |

## 2. 技术选型

| 项 | 选择 | 理由 |
|---|---|---|
| 框架 | Vue 3 + Composition API + `<script setup>` | 表单/表格密集，模板写法可读性最好 |
| 语言 | TypeScript | 条目、风险评定值、API 契约都需要类型约束 |
| 构建 | Vite | 输出纯静态产物，符合现有 adb 部署 |
| 路由 | Vue Router 4，**hash 模式** | 后端只需伺服 `/` 与 `/assets`，无需 SPA 回退规则 |
| 状态 | Pinia | 轻量，够用；不引入更重的方案 |
| 请求 | 原生 `fetch` + 薄封装 | 少一个依赖，板端离线更可控 |
| Markdown | marked（沿用） | 报告正文渲染，现有版本已在板端验证 |
| 单元测试 | Vitest | 覆盖 domain 纯函数 |
| 视口回归 | Playwright（开发机） | 在 600×960 / 960×600 下实跑断言 |
| UI 组件库 | **不引入** | 视觉需贴合机构规范，第三方库反而要大量覆盖 |

依赖控制在 5 个运行时包以内（vue、vue-router、pinia、marked），其余为开发依赖。

## 4. 分层与组件边界

### 4.1 四层职责

| 层 | 职责 | 不做什么 |
|---|---|---|
| `api/` | 与后端通信、鉴权头、错误归一 | 不存放业务规则，不做界面判断 |
| `domain/` | 纯函数：校验、风险计算、格式化 | 不访问网络、不碰 DOM |
| `stores/` | 报告与登录的单一状态源 | 不直接拼 HTML |
| `components/` | 渲染与交互 | 不写业务规则，规则从 domain 取 |

### 4.2 UI 组件（自研，约 8 个）

|---|---|
| `AppButton` | 主/次/危险三级，直角，30/36px 两档高度 |

| `AppField` | 标签 + 控件 + 错误信息 |

### 4.3 业务组件

| 组件 | 说明 |

## 5. 关键设计决策

### 决策 1　路由用 hash 模式

后端 `main.py` 目前只有写死的路由，没有静态挂载。若用 history 模式，刷新 `/report` 这类深层路径会 404，必须再加 SPA 回退规则。hash 模式的地址形如 `/#/report`，服务端永远只需要伺服 `/`，改动面最小。

### 决策 2　条目目录上提为后端资源

现状：66 条条目由 docx 抽取后写死在前端 JS 中。

改为：

```text
模板 docx
   ↓ tools/gen_jte_items.py（生成脚本入库，可重复执行）
backend/app/data/jte_items.json
   ↓ GET /api/report/jte-items
前端 domain/jteItems.ts（TS 类型 + 索引）
```

理由有三条：一是条目是业务数据，不属于界面代码；二是将来要挂知识图谱映射，加一个 `kg_item_id` 字段即可，前端不用改；三是替换模板版本时只跑一次脚本。

### 决策 3　报告模板独立成组件

附页、附录A、评价结果表不再由 JS 字符串拼接，改为 Vue 组件。这样模板改版时改的是模板文件，不是业务代码，也不会因为拼接字符串引入转义错误。

### 决策 4　风险评定值与附录A 走纯函数

`domain/riskScore.ts` 提供：

```text
CAT_VALUE      Ⅰ=0  Ⅱ=-1  Ⅲ=2
computeG(vs)   G = 100·Σv/(2n)；存在 v=0 或 Σv<0 时 G=0
gradeOf(G)     G≥90 一级 / ≥75 二级 / ≥60 三级 / 否则四级
```

这些是规范定义的确定性计算，与知识图谱、大模型无关，必须可单元测试、结果可复现。大模型只负责文字表述，不参与定级。

### 决策 5　竖屏优先的断点策略

断点取 **900px**：

- `> 900px`（横屏 960×600）：信息表四列、条目四列表格。
- `≤ 900px`（竖屏 600×960）：信息表逐字段堆叠、条目改为卡片式纵向排列，三态按钮满宽。

触摸目标高度不小于 44px，底部操作条在竖屏下分两行。

### 决策 6　报告预览按比例缩放，不重排

报告是固定版式的公文，重排会破坏与模板的一致性。A4 宽度 210mm ≈ 793px，超出竖屏 600px 时用 `transform: scale()` 整体缩放，外层容器同步设置高度，保持等比。

## 6. 构建与部署

### 6.1 构建

```bash
cd web
npm install
npm run build      # 输出到 web/dist/
```

产物：`dist/index.html`、`dist/assets/*.js`、`dist/assets/*.css`，以及 `public/` 下的 logo 与字体。

### 6.2 后端改动（`backend/app/main.py`）

必须新增静态挂载，否则 `/assets/*` 会 404、页面白屏：

```python
from fastapi.staticfiles import StaticFiles

WEB_DIR = ROOT_DIR / "web"
DIST_DIR = WEB_DIR / "dist"

# 挂载构建产物；目录不存在时跳过，保证开发期不报错
if (DIST_DIR / "assets").is_dir():
    app.mount("/assets", StaticFiles(directory=DIST_DIR / "assets"), name="assets")

@app.get("/", response_class=HTMLResponse)
async def serve_frontend():
    index_path = DIST_DIR / "index.html"
    if not index_path.exists():
        index_path = WEB_DIR / "index.html"      # 回退到旧版
    if index_path.exists():
        return index_path.read_text(encoding="utf-8")
    return "<h1>Frontend not found</h1>"
```

要点：

1. 挂载必须在 `include_router` 之后声明，避免抢占 `/api/*`。
2. 保留旧 `web/index.html` 作为回退，迁移期可随时切回。
3. `marked.min.js` 的现有路由保留，新工程改为 npm 依赖后可由打包产物提供。

### 6.3 push.bat 改动

```text
[1] 检查 adb 连接
[2] cd web && npm run build          ← 新增：先构建
[3] adb push web\dist\ /home/ubuntu/elevator/web/    ← 推送产物
[4] adb push backend\app /home/ubuntu/elevator/backend/
[5] 清理 __pycache__ 并重启 elevator-api
[6] 校验：curl / 返回 200，且页面引用的 assets 文件存在
```

第 6 步是必需的：构建产物与后端路径不匹配时表现为白屏，而白屏在板端很难排查。

### 6.4 构建产物是否入库

建议 **不入库**，在 `.gitignore` 中排除 `web/dist`。理由：产物可由源码重建，入库会让每次前端改动都产生大量 diff，也会让「源码版本」与「产物版本」不一致。

代价是部署前必须能构建。由于部署本来就在开发机执行，且 `npm install` 可离线缓存，认为可接受。

## 7. 测试与验证

### 7.1 单元测试（Vitest）

覆盖 `domain/` 全部纯函数，这是规范要求可复现的部分：

| 用例 | 期望 |
|---|---|
| 全部符合（无风险情节） | G = 100，一级 |
| 全 Ⅲ 类 | G = 100，一级 |
| 全 Ⅱ 类 | Σv < 0 → G = 0，四级 |
| 存在 Ⅰ 类 | G = 0，四级（一票否决） |
| Ⅰ类 + 其余 Ⅲ 类 | G = 0，四级 |
| 混合 Ⅱ/Ⅲ 且 Σv ≥ 0 | 按公式计算，等级落区间正确 |
| 漏填判定：未选评价结果 | 进入漏填清单 |
| 漏填判定：不符合但未填情形 | 进入漏填清单，且勾选「其他」后填写即通过 |
| 漏填判定：四个必填字段为空或为「/」 | 进入漏填清单 |

### 7.2 视口回归（Playwright，开发机）

在 **600×960** 与 **960×600** 两种视口下各跑一遍核心链路，断言：

1. `document.documentElement.scrollWidth <= viewport.width`（无横向溢出）。
2. 66 条条目全部渲染。
3. 三态切换、不符合情形展开、「其他」输入可用。
4. 漏填清单出现且点击可跳转定位。
5. 生成报告后附页、附录A 渲染，G 与等级符合预期。
6. 页面无 `pageerror` 与 console error。

### 7.3 板端实机清单

1. `curl http://127.0.0.1:8081/` 返回 200，页面引用的 `assets` 文件全部 200。
2. 触摸屏三态按钮可点，无误触。
3. 竖屏与横屏（陀螺仪旋转）下版式均正常。
4. 软键盘弹出时可输入中文；中文候选窗未被软键盘遮挡。
5. 导出 PDF / Word 成功，「打开文件」可打开产物。
6. 断电重启后自动进入系统，无白屏。

## 8. 分阶段实施

### 一期（核心链路，可上板验收）

1. Vite + Vue 3 + TS 工程骨架、设计令牌、基础 UI 组件。
2. 登录（沿用现有 `/api/auth/*`）。
3. 报告录入：抬头信息表 + 66 条条目 + 三态选择 + 不符合情形。
4. 漏填校验与跳转定位。
5. 报告预览：正文页、评价结果表（含风险评定值）、附页、附录A。
6. 导出 PDF / Word 与结果卡片。
7. 后端静态挂载 + push.bat 构建推送。

### 二期（边角功能）

草稿防抖保存、历史记录、用户管理、中英输入法切换、退出系统、开机自检提示。

### 迁移期策略

旧 `web/index.html` 保留在 `_archive`，后端 `serve_frontend` 保留回退逻辑。一期上板验证通过后再移除回退。

## 10. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 板端 WebKit 对部分 CSS 支持不足 | 版式在开发机正常、上板异常 | 只用 WebKit 2.44 支持的特性；关键 CSS 上板前用板端 WebView 实测 |
| 构建产物与后端路径不匹配 | 白屏，且板端难排查 | push.bat 增加产物校验步骤；保留旧版回退 |
| 竖屏触摸误触 | 现场录入效率下降 | 触摸目标 ≥44px；三态按钮满宽；危险操作二次确认 |
| 软键盘与自绘弹窗冲突 | 无法输入中文 | 沿用现有代码已验证的结论：弹窗自绘、不用原生 confirm、滚动约束在内容区 |
| 引入构建步骤后部署变复杂 | 现场运维可能漏构建 | push.bat 一条命令完成构建 + 推送 + 校验 |
| 一期范围蔓延 | 交付延期 | 二期功能在一期一律不实现，只预留接口 |
