## 1. 通用约定

### 1.1 基础

| 项 | 约定 |
| --- | --- |
| 基地址 | `http://127.0.0.1:8081`（板端本机；局域网访问见 §1.9） |
| 路径前缀 | 业务接口统一 `/api/**`；静态资源 `/assets/**`、`/`、`/fslogo.png` 等 |
| 编码 | UTF-8；请求与响应均 JSON（导出下载、SSE 除外） |
| 时间格式 | ISO 8601 本地时间字符串，如 `2026-10-13T09:30:00`（板端无时区需求） |
| 请求体 | `application/json`；GET 用查询串 |
| 幂等 | 读接口天然幂等；写接口的幂等策略见 §1.5 |

### 1.2 鉴权

1. 除白名单外，所有 `/api/**` 均要求登录。
2. 令牌放在请求头：`Authorization: Bearer <token>`（兼容不带 `Bearer` 前缀的写法）。
3. **白名单**（无需登录）：`POST /api/auth/login`、`POST /api/auth/forgot-password`、
   `GET /api/setup/status`、`POST /api/setup/init`、`GET /api/health`、`GET /api/health/ready`、
   `GET/POST /api/kiosk/*`（仅本机可调，见 §3.10）。
4. **单角色**：登录即拥有全部功能权限，接口不再有"仅管理员"这一档（见 PRD §3）。
5. 令牌失效的接口一律返回 **401**，前端统一跳登录页，不弹系统框。
6. 令牌生命周期：默认空闲 8 小时（`session_ttl_hours`），改密/停用即失效（见 §3.2）。

### 1.3 响应结构

成功：

```json
{ "success": true, "…业务字段…": "…" }
```

失败（HTTP 状态码同时给出语义）：

```json
{ "success": false, "detail": "可读的中文原因" }
```

约定：

1. `detail` 必须是人能看懂、能据此采取行动的一句话，**不得透出堆栈、异常类名、内部路径**。
2. 列表类响应统一带 `total`；分页另带 `page` / `size`。
3. 时间字段一律字符串，不返回时间戳。

### 1.4 分页与筛选

| 参数 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `page` | int | 1 | 从 1 开始 |
| `size` | int | 20 | 上限 100 |
| `q` | string | — | 模糊检索（编号 / 使用单位 / 姓名等，按接口定义） |
| `from` / `to` | string | — | 日期区间（含边界），格式 `YYYY-MM-DD` |
| `status` | string | — | 状态筛选，取值随接口定义 |
| `sort` | string | `-created_at` | `-` 前缀表示倒序 |

### 1.5 幂等与二次确认

1. **创建类**（开户、新建报告）：客户端可带 `client_token`（UUID）。服务端在同一账号下
   见相同 token 时返回既有结果，不重复创建 —— 防的是触摸屏连点两下。
2. **破坏性操作**（删除报告、作废、停用账号、重置口令、恢复备份）必须带
   `"confirm": true`。缺这个字段直接 400，避免误触。
3. 破坏性操作一律写审计日志（见 §1.7）。

### 1.6 错误码

| 状态码 | 语义 | 典型 detail |
| --- | --- | --- |
| 400 | 参数或业务规则不满足 | 原口令不正确 / 需要二次确认 |
| 401 | 未登录或令牌过期 | 未登录或登录已过期 |
| 403 | 已登录但被拒绝 | 账号已停用 / 退出功能已禁用 |
| 404 | 目标不存在 | 报告不存在 |
| 409 | 冲突 | 用户名已存在 / 报告编号重复 |
| 422 | 字段校验失败 | 口令强度不足 |
| 503 | 依赖未就绪 | 图谱服务未就绪 / 导出目录不可用 |
| 500 | 其它服务端异常 | 只给可读原因 |

### 1.7 审计约定

服务端在**业务成功之后**写审计事件（写失败不影响主流程，但要进服务日志）。每条事件包含：

| 字段 | 说明 |
| --- | --- |
| `at` | 发生时间 |
| `actor_id` / `actor_name` | 操作者账号（系统自动行为留空） |
| `event` | 事件类型，见下表 |
| `target` | 操作对象（账号名 / 报告编号 / 配置键） |
| `before` / `after` | 变更前后值（仅配置与账号类事件） |
| `result` | `ok` / `fail` |
| `note` | 备注（失败原因、来源等） |

需要落日志的事件（PRD FR-9.3）：

`login_ok`、`login_fail`、`logout`、`password_change`、`password_reset`、
`account_create`、`account_update`、`account_disable`、`account_enable`、`account_delete`、
`setup_init`、`report_create`、`report_generate`、`report_export`、`report_void`、`report_delete`、
`config_update`、`backup_create`、`backup_restore`、`clock_set`、`kiosk_exit`。

### 1.8 版本与兼容

1. 路径不带版本号（单机单客户端，无多版本并行需求）。
2. 新增字段只做加法；删除/改名字段必须同步改前端，不保留兼容层。
3. 前端入口 HTML 不缓存、`/assets` 带内容哈希可长缓存（已有约定，见 `main.py`）。

### 1.9 网络边界

1. 默认只监听 `127.0.0.1`。若现场需要局域网访问（例如机构想用电脑看报告），
   必须显式打开配置项，并在文档里写明风险 —— 目前**按不开处理**。
2. `POST /api/kiosk/exit` 额外校验来源必须是本机回环地址（已有实现）。

### 1.10 ID 约定（重要）

内部主键是**雪花 ID**（64 位整数，见《数据库设计 v1》§5），它**超出 JS 的安全整数范围**，
所以：

1. **JSON 里的 `id` 一律是字符串**：`{"id": "532918374650120192"}`，不是数字。
2. **路径参数按字符串接收**：`GET /api/reports/532918374650120192`，服务端再转 int 查库。
3. 前端**不对 id 做数值运算**，只做等值比较与拼接。
4. 报告的业务编号 `report_no`（如 `GDSEI-JTE-20261013-001`）本身就是字符串，不受影响。

违反这条会得到一个很隐蔽的 bug：id 末几位被四舍五入，请求别人或请求不到。

## 3. 详细设计

### 3.1 初始化与认证

#### GET `/api/setup/status`　公开

前端启动后第一件事：判断要不要进初始化向导、能不能给「忘记口令」入口。

| 响应字段 | 类型 | 说明 |
| --- | --- | --- |
| `initialized` | bool | 账号表是否已有账号。`false` → 必须走初始化向导 |
| `recovery_available` | bool | 板端是否配了恢复口令文件（决定登录页是否显示「忘记口令」） |
| `version` | string | 版本号，用于部署后核对 |

#### POST `/api/setup/init`　公开（仅当 `initialized=false`）

创建第一个账号。**不可跳过**：未初始化前其余业务接口一律 409。

| 请求字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `display_name` | string | 是 | 真实姓名，进报告与留痕 |
| `username` | string | 是 | 登录名，唯一 |
| `password` | string | 是 | 口令（强度规则见 §1.6 / PRD FR-1） |
| `password_confirm` | string | 是 | 二次确认 |

| 响应字段 | 说明 |
| --- | --- |
| `success` / `user` / `token` / `expires_at` | 创建后直接登录，省掉一次输入 |

错误：`409` 已完成初始化；`400` 两次口令不一致；`422` 口令强度不足。审计：`setup_init`。

#### POST `/api/auth/login`　公开

| 请求字段 | 类型 | 说明 |
| --- | --- | --- |
| `username` | string | 登录名 |
| `password` | string | 口令 |

| 响应字段 | 说明 |
| --- | --- |
| `success`、`token`、`expires_at` | 令牌与到期时间 |
| `user` | 账号信息（见 §4.1） |
| `must_change_password` | 是否需强制改密（开户/重置时勾了"要求首登改密"） |

错误：

- `401` **统一文案**「用户名或口令不正确」，不区分"账号不存在 / 口令错误 / 已停用"，避免枚举账号。
- `429` 口令错误次数超限：「口令错误次数过多，请 N 分钟后再试」。

审计：成功 `login_ok`；失败 `login_fail`（含失败次数与来源）。

#### POST `/api/auth/logout`　需登录

吊销当前令牌。审计 `logout`。响应 `{success:true}`。

#### GET `/api/auth/me`　需登录

返回 `{success, user, must_change_password}`。前端刷新时用它校验登录态是否还有效。

#### POST `/api/auth/change-password`　需登录

| 请求字段 | 说明 |
| --- | --- |
| `old_password` | 原口令（必须再验一次，防令牌被盗后直接改密） |
| `new_password` | 新口令 |

行为：成功后**吊销该账号全部会话**（含当前），前端跳登录页并提示。
错误：`400` 原口令不正确；`422` 强度不足 / 与最近 3 次重复。审计 `password_change`。

#### POST `/api/auth/forgot-password`　公开（需恢复口令文件）

给"所有人都忘了口令"留的出口（PRD FR-2 / Q14）。

| 请求字段 | 说明 |
| --- | --- |
| `recovery_key` | 板端 `/userdata/elevator/recovery.key` 的内容 |
| `username` | 要重置哪个账号 |
| `new_password` | 新口令 |

错误：`403` 恢复口令不正确；`404` 账号不存在；`503` 板端未配置恢复口令文件。
审计：`password_reset`（note 标注"恢复口令"）。

### 3.2 账号管理

单角色下这些接口**只要求登录**（现状要求管理员，要改）。

#### GET `/api/accounts`

查询参数：`status`（`active` / `disabled` / 省略=全部）、`q`（姓名或登录名）、`page`、`size`。

| 响应字段 | 说明 |
| --- | --- |
| `total`、`page`、`size`、`items[]` | 列表 |
| `items[].id` / `username` / `display_name` / `employee_no` | 账号标识 |
| `items[].is_active` | 是否启用 |
| `items[].created_at` / `last_login_at` | 时间 |
| `items[].report_count` | 该账号的报告数（界面据此提示"删除 vs 停用"） |

#### POST `/api/accounts`

| 请求字段 | 必填 | 说明 |
| --- | --- | --- |
| `display_name` | 是 | 姓名 |
| `username` | 是 | 登录名，唯一，创建后不可改 |
| `password` | 是 | 初始口令 |
| `employee_no` | 否 | 工号 |
| `require_change` | 否 | 是否要求对方首次登录改密，默认 `false` |
| `client_token` | 否 | 防连点，见 §1.5 |

错误：`409` 用户名已存在；`422` 口令强度不足。审计 `account_create`。

#### PATCH `/api/accounts/{id}`

请求：`display_name?`、`employee_no?`、`is_active?`。

规则：

1. `is_active=false`（停用）必须带 `confirm:true`，且**不允许停用最后一个启用账号**。
2. 停用后立即吊销该账号全部会话。
3. 不允许把 `is_active` 改回 `true` 之外的隐式行为 —— 启用就只启用，不动口令。

审计：`account_update` / `account_disable` / `account_enable`（含前后值）。

#### DELETE `/api/accounts/{id}?confirm=true`

规则：该账号有报告或草稿时返回 `409`「该账号已有 N 份报告，只能停用」，保留可追溯性。
审计 `account_delete`。

#### POST `/api/accounts/{id}/reset-password`

请求：`new_password`、`confirm:true`、`require_change?`。
行为：重置口令并吊销该账号全部会话。审计 `password_reset`。

#### 会话管理（P1）

- `GET /api/auth/sessions` → `items[]`：`id`、`username`、`display_name`、`created_at`、`expires_at`、`last_seen_at`、`current`（是否当前会话）。
- `DELETE /api/auth/sessions/{id}?confirm=true` → 强制下线。审计 `session_revoke`。

### 3.3 条目与依据（沿用）

| 接口 | 响应要点 |
| --- | --- |
| `GET /api/report/jte-items` | `{success, count, items[]}`；`items[].{no,name,sub,req[],opts[]}`。66 条，顺序即报告顺序 |
| `GET /api/report/inspection-items` | 图谱检测项目，按子系统分组（调用链用） |
| `GET /api/report/assessment-basis` | 评估依据文本（Neo4j 条款节点） |

说明：条目原文里的 `a) b) 1)` 是模板排版标记，**接口原样返回**，
由前端在渲染时去掉（`web/src/domain/format.ts`）。保持原文便于与模板对账。

### 3.4 报告作业

一条报告记录贯穿全生命周期（草稿 → 已生成 → 已归档 → 已作废），
因此不再需要"草稿单独存一份"。

#### POST `/api/reports`

新建空草稿。

| 请求字段 | 说明 |
| --- | --- |
| `form` | 可选，预填抬头（如"复制上一份"场景） |
| `client_token` | 防连点 |

响应：`{success, report: ReportSummary}`（见 §4.2）。审计 `report_create`。

#### PUT `/api/reports/{id}`

保存填写内容（前端自动保存用，防抖 800ms）。

```json
{
  "form": { "clientName": "…", "userName": "…", "deviceCategory": "…", "productNo": "…" },
  "items": [
    { "no": "1.7", "result": "fit", "reasons": [], "other_text": "" },
    { "no": "2.1", "result": "unfit", "reasons": ["箱体出现裂纹"], "other_text": "" }
  ],
  "version": 3
}
```

| 字段 | 取值 | 说明 |
| --- | --- | --- |
| `items[].result` | `fit` / `unfit` / `na` / `""` | 符合 / 不符合 / 无此项 / 未填 |
| `items[].reasons` | string[] | 勾选的不符合情形（多选） |
| `items[].other_text` | string | "其他（自行填写）"的内容 |

响应：`{success, saved_at, counters:{total,done,unfit,missing}}`

规则：

1. 只有 `draft` / `generated` 状态可改；`filed`（已归档）要改必须先"重新生成"。
2. 已生成的报告再修改，`status` 回退为 `draft`、`version+1`，旧的风险值作废（见 PRD 4.2）。
3. 带 `version` 时做乐观锁：不匹配返回 `409`（防两台设备同时改同一份 —— 虽然单机，但浏览器多标签也会遇到）。

#### GET `/api/reports/{id}/draft`

续录用：直接返回 `{success, form, items, counters}`，不需要前端再拼。

#### POST `/api/reports/{id}/generate`

生成报告：拉图谱 → 规则判定风险评定值 → 计算 G 与等级 → 组装附页/附录A。

| 请求字段 | 说明 |
| --- | --- |
| `use_llm` | 默认 `true`；`false` 时只用图谱 + 规则（模型不可用时的降级，见 PRD 4.3） |
| `client_token` | 防连点 |

| 响应字段 | 说明 |
| --- | --- |
| `report` | ReportSummary（此时 `report_no` 已分配、`status=generated`） |
| `risks` | `{ "2.1": {severity, probability, category, source, evidence} }`，键为项目编号 |
| `score` / `grade` | 综合安全状况得分 G 与等级 |
| `narrative` | 叙述性文字（大模型产物或图谱摘要兜底） |
| `provenance` | 溯源：图谱链路条数、规则命中、是否用模型、耗时、条目库版本 |

错误：`400` 有漏填（`detail` 给出缺失项列表）；`503` 图谱未就绪（此时录入与草稿不受影响）。
审计 `report_generate`（含是否用模型、耗时）。

#### POST `/api/reports/{id}/generate-stream`

同一件事的流式版本：**数值已在上一步算好**，这里只负责把叙述文字逐段推给前端。

SSE 事件格式：`data: {"t":"片段"}` … 结束 `data: {"t":"[DONE]"}`。
模型失败时推 `{"t":"[模型调用失败]"}`，但报告仍然成立（降级标识写在 `provenance.llm_used=false`）。

### 3.5 报告管理

**报告编号规则（2026-10-13 定）**：`{机构前缀}-{YYYYMMDD}-{3 位当日流水}`，
默认前缀 `GDSEI-JTE`（配置项 `report_no_prefix`），流水按日重置，作废号不复用。
例：`GDSEI-JTE-20261013-001`。完整时间戳（`created_at` / `generated_at` / `assessed_on`）
单独保存在报告记录里，编号只承担"标识 + 当天可读"。

#### GET `/api/reports`

查询参数：`status`、`q`（编号 / 使用单位）、`from`、`to`、`mine`（`true` 只看自己，默认 `false`）、`page`、`size`、`sort`。

响应：`{success, total, page, size, items:[ReportSummary]}`。

#### GET `/api/reports/{id}`

响应：`ReportDetail`（§4.3），含填写内容、风险值、得分等级、叙述文字、溯源信息、导出文件记录。

#### POST `/api/reports/{id}/void`

请求：`reason`（必填）、`confirm:true`。
行为：`status=void`，**报告编号保留不复用**。审计 `report_void`（含原因）。

#### POST `/api/reports/{id}/clone`

复制为新的草稿（换电梯时复用抬头，现场高频动作）。响应新的 `ReportSummary`。
新草稿不含原报告的评价结果 —— 避免上一条电梯的判定被误当本次结果（PRD Q4 同源问题）。

#### DELETE `/api/reports/{id}?confirm=true`

仅 `draft` / `void` 可删；`generated` / `filed` 只能作废。审计 `report_delete`。

### 3.6 导出

#### POST `/api/report/export`　需登录（改造）

现有实现由**前端把渲染好的 HTML 传过来**。改为**只传报告 id**，服务端自己渲染：

1. 报告内容可复现（同一份报告今天导出与三个月后导出必须一致）；
2. 服务端才能算出并记录文件的 SHA-256（PRD FR-5 要求）。

| 请求字段 | 必填 | 说明 |
| --- | --- | --- |
| `report_id` | 是 | 要导出的报告 |
| `fmt` | 是 | `pdf` 或 `docx` |
| `filename` | 否 | 不带扩展名；留空按规范生成 |

| 响应字段 | 说明 |
| --- | --- |
| `fmt` / `filename` / `path` / `dir` / `size` / `sha256` | 产物信息 |
| `report_no` | 报告编号（导出时若尚无编号要先分配） |

文件名规范：`{报告编号}_{使用单位}_{yyyyMMdd}.pdf`；同名重复导出追加 `_2`、`_3`，
不覆盖旧文件。导出前预检：LibreOffice 可用、导出目录可写、磁盘剩余空间充足。

错误：`400` 格式不支持；`503` 导出目录不可用 / 缺少转换器；`500` 其它（给可读原因，不透出堆栈）。
审计 `report_export`（含文件名与大小）。

#### POST `/api/report/open`　需登录（沿用）

请求：`target`（文件或目录路径）。**只允许导出目录内的路径**，否则 `400`；不存在 `404`。

### 3.7 系统配置与审计

> **基础版口径（2026-10-13）**：配置仍放在 `.env`（部署期设定），
> `GET /api/system/config` 只做**只读展示**；`PUT` 与"配置变更历史"随配置界面一起放到 P1，
> 届时配置落库（`app_config` + `config_history`）。接口形状不变，只是先不做写。

#### GET `/api/system/info`

给「关于」页与诊断用，响应：

| 字段 | 说明 |
| --- | --- |
| `version` | 系统版本 |
| `model` | 大模型名称与来源（如 `Qwen3.5-4B / RKLLM`） |
| `catalog` | 条目库：`version`、`count`、`hash` |
| `kg` | 图谱规模：`nodes` / `relations` |
| `deps` | 依赖状态：`neo4j` / `rkllm` / `libreoffice` |
| `db` | 业务库路径与大小 |
| `export_dir` / `disk_free` | 导出目录与剩余空间 |

#### GET `/api/system/config`

响应：`{success, items:[{key, value, type, editable, desc, updated_at}]}`。
配置项来自数据库（不再只靠 `.env`），每项带是否可在界面修改。

#### PUT `/api/system/config`

请求：`{changes: {"session_ttl_hours": 8, …}, confirm:true}`。
行为：逐项写入 + 记录变更历史（基础版先写审计 `config_update`；P1 落 `config_history` 表）。
需要重启才生效的项在响应里标出：`{success, applied:[], restart_required:[]}`。

#### GET `/api/system/audit`

查询参数：`from`、`to`、`event`、`actor`、`result`、`page`、`size`；`format=csv` 时直接返回文件。
响应：`{success, total, page, size, items:[AuditEvent]}`。

### 3.8 备份与恢复

#### POST `/api/system/backup`

| 请求字段 | 说明 |
| --- | --- |
| `target_dir` | 可选，默认 `/userdata/backup/{yyyyMMdd-HHmmss}`；支持 U 盘挂载路径 |

行为：打包业务库 + 导出目录 + 配置快照 + 条目库版本，写 `manifest.json`（文件清单 + SHA-256），
并按保留策略清理旧备份（默认保留 10 份）。

响应：`{success, dir, files[], size, manifest}`。审计 `backup_create`。

#### POST `/api/system/restore`

请求：`{dir, confirm:true}`。
行为：先校验 manifest → **自动备份当前状态** → 写临时文件 → 原子替换 → 返回需重启提示。
响应：`{success, pre_backup, restart_required:true}`。审计 `backup_restore`。

### 3.9 运维与诊断

#### GET `/api/system/diagnose`

一次性把该查的都查了（对应板端 `diagnose.sh`）：

```json
{ "success": true, "checks": [
  { "name": "Neo4j", "status": "ok|warn|fail", "detail": "…", "advice": "…" }
] }
```

检查项：Neo4j 连通、RKLLM 可用、磁盘剩余、导出目录可写、系统时间偏移、
LibreOffice 可用、中文字体、业务库完整性（`PRAGMA integrity_check`）、条目库文件存在。

在 `ReportSummary` 基础上追加：

| 字段 | 说明 |
| --- | --- |

### 4.4 RiskValue

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `severity` | int | 严重程度 |
| `probability` | string | 概率等级 |
| `category` | string | 风险类别（Ⅰ / Ⅱ / Ⅲ） |

| `evidence` | object | 依据（图谱节点 id、命中的规则、条款） |

### 4.5 AuditEvent

`at` / `actor_id`（string）/ `actor_name` / `event` / `target` / `before` / `after` / `result` / `note`（见 §1.7）。

### 4.6 枚举速查

| 枚举 | 取值 |
| --- | --- |
| 报告状态 | `draft` 草稿 / `generated` 已生成 / `filed` 已归档 / `void` 已作废 |

| 综合等级 | 一级 / 二级 / 三级 / 四级 |
| 导出格式 | `pdf` / `docx` |

## 6. 与现状的差异与迁移

| 现状 | 目标 | 处理 |
| --- | --- | --- |
| `GET/POST /api/history`、`GET/PUT/DELETE /api/draft` | `/api/reports`（一条记录贯穿生命周期） | 新增 `/api/reports`；旧数据迁移：`report_history` → `status=filed`，`form_draft` → `status=draft`；旧路径保留一个版本后删除 |
| `GET/POST/PATCH/DELETE /api/auth/users`（需管理员） | `/api/accounts`（登录即可） | 换路径与鉴权口径；保留"最后一个启用账号"保护 |
| 首启预置 `admin/admin123` | 初始化向导 | 去掉预置账号，改为 `POST /api/setup/init` |
| `POST /api/report/generate`（按检测项 id） | `POST /api/reports/{id}/generate`（按报告） | 新接口按报告取数，图谱查询逻辑复用 |
| `POST /api/report/export`（前端传 HTML） | 同名接口（传 `report_id`） | 服务端渲染，便于记录 SHA-256 与复现 |
| 无审计、无配置、无备份 | §3.7 / §3.8 | 全新增，配合《数据库设计 v1》建表 |

**迁移原则**：脚本幂等、可重复执行；迁移前自动备份；迁移失败要能回滚（配合数据库版本化迁移）。
