# 风险录入与评定接口和数据设计

日期：2026-10-15。版本：v0.1。状态：技术草案，未实现；不代表 PRD 待确认规则已获批准。

2026-10-16范围说明：本文较大的v2接口/快照方案未执行，作为历史草案保留。当前采用现有接口、五张表，更换风险选项及生成算法；实际实现和上板结果以[本次实施与验收](风险材料接入-本次实施与验收.md)为准。

依据：[风险录入与评定 PRD](../prd/PRD-风险录入与评定变更-v0.1.md)、[原文核对结果](../prd/risk-review-v1/规则对照与待确认问题.md)。本文补充现有接口、数据库及前端设计，不改登录、角色、部署结构。

## 1 本次技术决定

1. 保留 FastAPI、SQLite、repo 层、Vue 3，继续使用现有五张业务表。
2. 专家风险目录和评定规则以版本化 JSON 随应用发布，业务报告保存快照；不新增风险管理后台或训练平台。
3. 保留 `/api/reports` 报告生命周期。新增三个路由：读取风险目录、解析自由描述、按报告快照导出。保存和生成仍用现有路由，增加明确的字段与校验。
4. 同项目所选风险类别取最严重者，I > II > III。严重程度、概率及计分口径由已批准规则决定；未批准时标记待定，不生成正式结果。
5. 不再依赖客户端提交的类别、措施或分数；风险目录、模型建议和检验员确认各有来源。

## 3 风险目录和规则文件

建议正式文件为 `backend/app/data/risk_catalog.json`、`risk_policy.json`。审核目录下的 `.review.json` 不作为运行输入。

### 3.1 风险标识和版本

- `risk_id`：固定字符串，如 `RISK-000001`。示例仅用于接口说明，目前尚未发布正式ID。
- 首次发布时分配ID并显式保存；后续重排不重新编号。不能把源表行号或审核定位键直接作为永久ID。
- 文案、类别、措施修订保留ID并增加目录版本；拆分、新增风险分配新ID，删除风险标记停用，旧版本继续保留以支持历史草稿。
- `risk_catalog_version`：目录的不可变版本标识；另存规范化JSON内容的完整SHA-256作为校验。计算时排除risk_catalog_version和content_hash字段，避免自引用，其余字段参与校验。
- 每条记录保留 `item_no`、原始风险、规范化类别、原始类别、措施原文、来源文件哈希及表行位置。
- `record_kind` 为 `risk`、`normal_observation`、`pending_review`；`selectable` 仅对已审定风险为true。39条正常描述和216行归属仍按PRD审核，不能靠类别直接发布。

### 3.2 分类与评定分开

目录中的具体风险类别使用 `I/II/III`，显示层映射为 `Ⅰ类/Ⅱ类/Ⅲ类`。v2报告项仍保留现有中文 `category` 字段以兼容组件，新增 `category_code` 用于规则比较；两者由服务端同时生成并验证一致。

`risk_policy.json` 保存24格矩阵、132条参考样例、已批准的项目/具体风险评定规则、计分口径和规则版本。样例不自动变成所有同类风险的确定规则。

当前目录文件保存最新已发布版本；历史目录归档在 `backend/app/data/risk_catalog/archive/`。加载器只通过已扫描并校验的版本映射选文件，不直接把用户版本字符串拼成路径。规则加载可返回无已发布规则，评定服务据此产生未决issue。

规则有 `publication_status=review/published`。未覆盖的情形返回具体未决原因。目录可已发布而计分规则未完整发布，此时允许录入和草稿，不允许伪造正式得分。

## 4 保存数据及所有权

### 4.1 v2保存请求

`PUT /api/reports/{report_id}` 采用下面的结构；form仍为现有完整抬头。示例中的ID、版本及哈希均为说明占位。

```json
{
  "schema_version": 2,
  "risk_catalog_version": "expert-YYYYMMDD-r1",
  "version": 1,
  "draft_etag": "sha256-placeholder",
  "form": {},
  "items": [
    {
      "no": "16.1",
      "result": "unfit",
      "risk_ids": ["RISK-000001"],
      "other_enabled": true,
      "other_text": "检验员输入的完整原文",
      "other_match": null,
      "measure_choices": []
    }
  ]
}
```

v2的结果枚举为 `""/fit/unfit/na`。`risk_ids`保存稳定ID；不再让 `reasons` 原文字符串承担关联键职责。v2不接受非空旧 `reasons`，防止重复含义。

`other_text`沿用现有500字符上限，保留原文，不因取消勾选而删除；`other_enabled`控制是否参与评定。改变结果时仍保留风险选择与文字，只有unfit参与风险处理。

`other_match` 为null，或：

```json
{
  "input_hash": "sha256-placeholder",
  "risk_ids": ["RISK-000002"],
  "method": "accept_suggestion"
}
```

`method`允许 `accept_suggestion/manual_match`。前者必须匹配服务端已有建议；后者表示检验员从已发布清单明确手动关联，不能伪称模型命中。客户端不提交确认人、时间、类别、严重程度、概率或措施。

`measure_choices`为可选数组，默认全部采用原文。元素为 `{risk_id, input_hash, choice}`，choice为 `original/suggestion`。接受suggestion仅能引用服务端同输入哈希下保存的该风险措施建议，且该风险在本项目有效集合内；服务端记录采用人和时间。客户端不能上传任意措施冒充模型建议。现阶段未有建议的直接风险一律采用原文；若需单独对其调用措施整理，另行明确交互，不隐含增加自动改写。

第一阶段自由描述通过匹配既有风险获得确定来源。无法匹配的内容保留为待确认，不能靠客户端自填类别绕过规则；如果需要“全新风险人工定级”，须先补PRD规则及依据，不在这里隐含增加功能。

### 4.2 服务端保存内容

`items_json`仍为数组。在v2答案上由service附加 `analysis` 和 `confirmed_match`：

- `analysis`：模型建议、候选risk_id、未匹配内容、措施解析建议、输入哈希、模型及提示词版本、时间、状态。
- `confirmed_match`：已核验风险ID、输入哈希、确认账号字符串ID、时间及确认方式。
- 保存时service合并服务器字段，不接受客户端伪造；同一输入未改变则保留，输入改变则旧建议及确认失效。
- 输入哈希覆盖项目编号、`other_enabled`、原始文字、排序去重后的直接risk_ids和目录版本。输入文字、所选风险或目录变更，都不能沿用旧确认。
- 非unfit、other未启用时，建议和确认可以暂存但不参与评定；切回后仅在输入哈希仍一致时使用。
- 客户端回传 `analysis/confirmed_match/score/category` 等受保护字段时，v2返回422，不静默采信。

`provenance_json.input`保存 `schema_version=2` 和风险目录版本。get/detail/draft接口回传完整已保存状态，避免刷新丢失候选建议和确认状态。

### 4.3 存储位置

| 数据 | 位置 |
| --- | --- |
| 完整录入、暂存选项、模型建议、确认状态 | report.items_json |
| 抬头完整状态 | report.form_json，现有检索投影列同步 |
| 项目评定和逐风险措施快照 | report.risks_json，继续按项目编号索引 |
| 目录、规则、输入和生成版本信息 | report.provenance_json |
| 最终综合分数与等级 | report.score、report.grade；未完成为null |
| 导出路径、大小、SHA-256、快照哈希 | report.files_json |
| 检验员确认和正式生成记录 | 现有audit_log |

不新增表，不改变SQLite user_version；这是JSON载荷版本升级。若后续发现现有列无法承载，再单独设计迁移，不提前加表。Snowflake报告ID对外仍是字符串。

## 5 内容ETag和事务

现有version仍表示报告业务版本，不能同时充当每次输入的修订号。新增 `draft_etag`，无需加列：对服务端当前 `form/items/catalog_version/template_version/status/version/provenance.input/provenance.generation_hash` 按固定字段集合构成对象，再用排序键、紧凑分隔符、UTF-8、ensure_ascii=false的规范JSON计算完整SHA-256；列表顺序保留，缺失的provenance.input按空对象、generation_hash按null处理。包含上次生成哈希以识别同输入并发生成的不同结果。

1. 创建、详情、续录、保存、解析、生成响应都返回 `version` 和 `draft_etag`。
2. v2保存、解析、生成请求必须携带这两项。保存和短事务写入均先 `BEGIN IMMEDIATE`，重新读取并比较；不同则409，禁止覆盖。
3. 普通读取及模型推理期间不持有写事务。解析/生成先取快照，模型结束后开启短事务复查ETag、状态和目录版本，生成还需复查所采用的rule_version和template_version，匹配才提交。
4. 生成编号只在成功提交结果的短事务内分配。失败或陈旧结果不分配编号、不覆盖新输入。
5. 保存成功响应至少包含 `success/counters/saved_at/version/draft_etag/status/schema_version/risk_catalog_version`。前端立即更新本地令牌。
6. 前端对同一报告串行保存；新输入若在保存中产生，待返回后再保存最新快照。切换报告前排空待保存；失败则留在原报告。迟到响应必须校验报告ID，不得覆盖新建报告。
7. 正式生成后的快照与draft_etag分别管理；导出采用 `generation_hash`，不以当前可变草稿作为导出依据。

## 6 路由约定

所有新路由沿用登录鉴权，检验员权限相同；继续使用 `success` 包装及字符串 `detail` 错误提示。

| 路由 | 用途 | 读写 |
| --- | --- | --- |
| GET /api/report/risk-catalog?version=... | 取得指定或当前已发布目录、66项关联、来源和版本 | 只读 |
| POST /api/reports | 创建v2空白草稿并锁定目录版本 | 写草稿 |
| PUT /api/reports/{id} | 保存完整v2输入及确认决定 | 写草稿 |
| GET /api/reports/{id} 及 /draft | 恢复状态、候选及确认、版本 | 只读 |
| POST /api/reports/{id}/risk-analysis | 解析指定项目已保存的其他文字 | 有条件写入建议，不自动确认 |
| POST /api/reports/{id}/generate | 校验、评定、生成唯一快照 | 有条件写入正式结果 |
| POST /api/reports/{id}/export | 根据已保存生成快照导出pdf/docx | 写文件及导出登记 |

### 6.1 目录读取

响应包含 `risk_catalog_version/publication_status/content_hash/template_version/items`。每个item有no及risk_options；每个risk_option含risk_id、text、category_code、measure、来源。正常观察可单列为reference_observations，不混入可选风险。

无已发布目录返回503/CATALOG_UNAVAILABLE，不能自动把审核数据当正式目录。指定未知版本404；历史已发布版本仍可读取。当前审核资料数量不等于最终发布选项数量。

创建v2报告在现有创建请求增加 `schema_version=2/risk_catalog_version`；服务端核验目录已发布后锁定版本，回传输入版本及ETag。未带schema_version仍按v1兼容，不能把旧客户端当作已支持新字段。

### 6.2 自由描述解析

请求：`{version, draft_etag, item_no}`。服务端从指定报告已保存文字读取，避免两份文字不一致。需要unfit、other_enabled及有效文字；使用该报告锁定目录中的同项目风险，不跨项目匹配。

响应包含 `success/item_no/version/draft_etag/analysis`，analysis.state为 `suggested/unmatched/unavailable`。模型只提出已知风险ID及措施整理建议，类别一律从目录取；未知ID剔除并将对应文本标为未匹配，不能当成功定级。

解析超时或模型不可用保存unavailable状态并保留用户原文，响应仍可读取该状态；不自动重试长调用。迟到结果遇到新ETag返回409，不写入过期建议。解析完成不能自动改变评价结果、勾选项或确认状态。

本路由推理上限90秒，现有模型配置更短时取更短值；前端仅对该路由使用110秒超时。通过Python 3.10可用的asyncio.wait_for限制调用，不修改全局请求默认超时。

### 6.3 正式生成

在现有 `use_llm/client_token` 外增加 `schema_version=2/version/draft_etag`。检查完整66项、编号唯一合法、四个必填字段、未决自由描述、ID所属项目及版本、规则覆盖、三元组与矩阵一致性。

有效风险集合为直接选择及启用文字的已确认匹配ID的并集；同一ID去重，其他风险仍完整保留。项目类别仅对这个集合取最严重值。

所有未决问题返回422，不调模型生成正式结论、不消耗编号。风险类别不能唯一决定严重程度/概率，Q1未覆盖时显式阻止相关正式生成；Q2未定时不自动选择一个分母。

模型仅在确定的事实快照上编写叙述或解析措施，不能写回类别、分数、等级。明确采用原文措施时可在无模型情况下生成；生成中出现未审定的改写措施，不自动采纳，仍保留来源原文。

### 6.4 快照导出

请求 `{fmt: "pdf"或"docx", generation_hash: "..."}`，不接受body_html、前端分数或措施。服务端以快照和已锁定模板生成HTML，复用LibreOffice转换。

仅generated/filed状态且generation_hash一致可导出；草稿或hash不同返回409。原 `/api/report/export`暂保留旧版兼容，不用于v2正式报告，也不作为“已验证内容一致”的依据。

响应沿用 `fmt/filename/path/dir/size`，增加 `report_id/generation_hash/sha256`。登记文件到files_json并写审计。转换期间不持有SQLite写锁，登记前复查状态和生成哈希；已作废或快照改变则不登记成功，孤立临时产物不出现在可交付结果中。

## 7 生成结果结构

`risks_json`继续按no索引，每个项目存：`severity/probability/category/category_code/source/assessment_state/selected_risks`。

- `selected_risks`每条有 `risk_id/text/category_code/measure_original/measure_adopted/measure_source/source_ref`。不得用类别通用措施覆盖具体措施。
- `severity/probability`在草稿待定时为null；正式生成时必须满足已批准规则或已明确的无此项输出规则。
- `assessment_state`为 `resolved/not_applicable/unresolved`；没有规则的情形不能冒充resolved。
- 附页行键使用 `item_no + risk_id`；正文项目级类别与附页逐风险类别分别显示含义，是否一风险一行仍须PRD最终确认。
- `provenance`保留现有顶层llm_used等字段，新增 `input/assessment_schema_version/risk_catalog_version/rule_version/template_version/generation_hash`，并保存实际采用的模板要求快照，包括12.4嵌套表。
- `generation_hash`计算范围为生成快照的form、项目输入与要求、risks、score、grade、narrative及版本，排除hash自身和可变导出文件列表。内容不因目录后续升级而改变。

历史报告打开和重导出使用已保存快照。现有report只存最新生成结果，本次不承诺可查看任意历史修订；若要求完整修订历史，应单独设计，不借此增加表。

上述完整快照保证适用于v2。v1记录没有完整模板或措施快照时保留其旧展示路径，明确来源状态；不能补造原始快照或声称可恢复当时完全相同的报告。

## 8 错误及兼容

错误示例（示意，尚无规则批准）：

```json
{
  "detail": "项目16.6尚未确定严重程度和概率等级",
  "code": "ASSESSMENT_UNRESOLVED",
  "issues": [
    {"item_no": "16.6", "field": "risk_value", "code": "RULE_UNRESOLVED", "message": "请先确定适用评定规则"}
  ]
}
```

`detail`保持字符串，现有前端仍可显示；新前端读取issues逐项跳转。422用于非法ID、错误项目关联、未确认文字、未覆盖规则；409用于ETag/目录冲突、过期建议或快照；503用于无可用目录；401沿用登录失效。

包括Pydantic字段校验在内的报告路由错误需要统一为这一结构，不能继续把数组放在detail而让客户端丢失原因。兼容处理限定在报告作业路由，不改变认证路由。前端ApiError保留可选code/issues。

v1历史items原文保留，provenance无input.schema_version时视为v1。不能用文字模糊匹配自动补风险ID、重算分数或声称是专家正式结果。

包含旧内容的v1草稿升级为v2须在v2保存请求中明确 `upgrade_confirm=true`，将原form/items及旧目录版本留在 `provenance.legacy_input`；逐项重新关联风险，不自动匹配。新的v2空白草稿无此升级步骤。旧前端写入已升级v2报告返回409/CLIENT_UPGRADE_REQUIRED，防止完整替换时清空新字段。升级及读取必须在实际JSON边界测试。
