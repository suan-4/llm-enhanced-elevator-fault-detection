## 1. 现状与差距

现有前端只有 **2 个页面**：登录页、报告页（录入与预览靠内部状态切换，不走路由）。

| 能力 | 现状 | 目标 |
| --- | --- | --- |
| 页面数 | 2 | 4 个导航页 + 3 个独立页（初始化向导 / 忘记口令 / 报告详情） |
| 路由 | `/login`、`/` | 见 §2 |
| 录入与预览 | 同一个组件里用 `view` 变量切换 | 拆成两个路由，预览按报告 id 打开 |
| 草稿 | 每人一份全局草稿（`/api/draft`） | 一份评估 = 一条报告记录（`/api/reports`） |
| 账号 / 报告 / 系统管理 | **完全没有** | 三个页面 |
| 启动兜底 | 有（资源加载失败给可读提示） | 保留并扩展 |

要**冻结**的部分：登录页与启动页的视觉、结构、文案一字不改
（验收脚本里已有回归项，见 §10）。

## 2. 路由与页面清单

| 路径 | 页面 | 何时进入 | 需要登录 |
| --- | --- | --- | --- |
| `/setup` | 初始化向导 | `GET /api/setup/status` 返回 `initialized=false` 时**强制跳入**，不可绕过 | 否 |
| `/login` | 登录页 | 未登录时的默认页 | 否 |
| `/login/forgot` | 忘记口令 | 登录页点「忘记口令」（仅当板端配了恢复口令时该入口才显示） | 否 |
| `/` | 评估录入 | 登录后的默认页 | 是 |
| `/reports` | 报告管理 | 侧栏「报告管理」 | 是 |
| `/reports/:id` | 报告详情 / 预览 | 列表点开、或生成报告后自动跳入 | 是 |
| `/accounts` | 账号管理 | 侧栏「账号管理」 | 是 |
| `/settings` | 系统设置（标签页：基本配置 / 审计日志 / 备份恢复 / 诊断 / 关于） | 侧栏「系统设置」 | 是 |

路由守卫规则：

1. 未初始化 → 一律重定向到 `/setup`（除白名单页面）。
2. 未登录访问受保护页 → 跳 `/login`，登录后回到原目标路径。
3. 已登录访问 `/login` → 跳 `/`。
4. **个人设置（改密、在线会话）用侧栏弹层，不占路由** —— 轻量动作不值得一次页面跳转。

## 3. 应用外壳

### 3.1 `App.vue` 的职责（保持精简）

1. 启动流程：`auth.restore()` + `kiosk.load()` + `setup.status()`，期间显示启动页。
2. 全局 Toast。
3. 输入法中英切换按钮（板端才显示）。
4. 启动兜底面板 + `app.config.errorHandler`。

**不放进 App.vue**：任何业务状态。业务状态一律进 store。

### 3.2 启动顺序

1. 挂载后并行发起三件事：`auth.restore()`（有令牌就校验）、`kiosk.load()`（是否一体机 / 输入法）、`setup.status()`（是否已初始化）。
2. `initialized = false` → 跳 `/setup`。
3. 有有效登录态 → 跳 `/`。
4. 否则 → 跳 `/login`。

三个请求任一失败都不能白屏：按"未初始化 / 未登录"的保守默认走，并在页面上给出可读提示。

### 3.3 外壳布局

与前一致：左侧可折叠导航（宽屏 260 / 折叠 50；窄屏 186 / 折叠 50）、顶部 52px 标题栏、底部悬浮岛。变化两点：

1. 导航项从 2 个增加到 4 个：**评估录入 / 报告管理 / 账号管理 / 系统设置**。
2. 悬浮岛**按页面显示**：

| 页面 | 悬浮岛内容 |
| --- | --- |
| 评估录入 | 计数（共/已评/不符合/未填）+ 保存草稿 + 校验并生成报告 |
| 报告详情 | 计数（只读）+ 导出 PDF + 导出 Word |
| 报告管理 / 账号管理 / 系统设置 | 不显示悬浮岛（用页面内工具栏） |

## 4. 页面详设

每页固定按「目的 / 布局 / 交互 / 接口 / 边界状态」写。

### 4.1 启动页与兜底面板（已有，保留）

- 启动页：联合 logo + 标题 + 英文副标题 + 加载动画 + 依据，至少显示 600ms。
- 兜底面板：资源加载失败、路由懒加载失败、8 秒未挂载、渲染异常 → 可读原因 + 「重新加载」。
  **这四条不能退化**，否则板端白屏时无从判断。

### 4.2 初始化向导 `/setup`（新增）

**目的**：账号表为空时创建第一个账号，取代预置的 `admin/admin123`。

| 区域 | 内容 |
| --- | --- |
| 顶部 | 系统名 + 一句说明「首次使用，请创建第一个账号」 |
| 表单 | 姓名、登录用户名、口令、确认口令（全部必填） |
| 底部 | 主按钮「创建并进入系统」 |

交互与规则：

1. 口令强度即时校验（≥8 位、含字母与数字），不满足时按钮置灰并给出原因。
2. 两次口令不一致即时提示。
3. 提交成功 → 直接登录 → 跳 `/`。
4. 若期间别的设备已完成初始化 → 后端 409，提示后跳 `/login`。
5. 用户名限 `[A-Za-z0-9_.-]`，开户后不可改（界面上要写明）。

接口：`GET /api/setup/status`、`POST /api/setup/init`。

### 4.3 登录页 `/login`（冻结，只加一个入口）

视觉、结构、文案**一字不改**。唯一新增：底部一行「忘记口令」文字链接，
且**仅当 `recovery_available=true` 时显示**（不给用不了的入口）。

### 4.4 忘记口令 `/login/forgot`（新增）

| 区域 | 内容 |
| --- | --- |
| 表单 | 恢复口令、要重置的用户名、新口令、确认新口令 |
| 按钮 | 「重置口令」+「返回登录」 |

成功后提示「已重置，请用新口令登录」并跳回登录页；恢复口令错误时统一提示
「恢复口令不正确」，不透露用户名是否存在。

接口：`POST /api/auth/forgot-password`。

### 4.5 评估录入页 `/`（现有，需改造）

**目的**：现场逐条录入 66 条评价结果。使用频率最高的一页。

页面有三种状态：

| 状态 | 触发条件 | 界面 |
| --- | --- | --- |
| 无进行中评估 | 没有任何草稿 | 空状态卡片：说明 + 「新建评估」按钮 |
| 有未完成草稿 | 存在 `status=draft` 的报告 | 卡片改为「有 N 份未完成的评估」列表（评估日期 / 使用单位 / 已完成条数），每条可「继续」或「删除」 |
| 正在录入 | 打开了某份草稿 | 抬头信息表 + 66 条条目表 + 悬浮岛计数 |

录入态的元素（沿用现有结构，已在设计稿中定稿）：

1. 页面标题「在用曳引驱动电梯安全评估报告」（黑体 22px 居中）。
2. 抬头信息表：**委托单位名称、使用单位名称、设备类别、产品编号** 四项必填，其余预填「/」。
3. 条目表：66 条按模板顺序连续排列；三态选择「符合 / 不符合 / 无此项」；
   选「不符合」展开情形多选 + 「其他（自行填写）」。
4. 悬浮岛：共 / 已评 / 不符合 / 未填 + 保存草稿 + 校验并生成报告。
5. 漏填提示条：页面顶部，逐条可点击 → 滚动定位 + 高亮 + 聚焦。

交互规则：

1. **自动保存**：任何改动后防抖 800ms 写 `PUT /api/reports/{id}`；悬浮岛显示「保存中… / 已保存 HH:MM」。
2. **手动保存**：「保存草稿」立即保存并 toast。
3. **生成前校验**：漏填则不请求后端，前端直接展开漏填清单。
4. **生成**：`POST /api/reports/{id}/generate` → 成功后跳 `/reports/{id}`；期间按钮「生成中…」并禁用；失败给可读原因。
5. **离开保护**：有未保存改动时离开（点侧栏）给二次确认。
6. **草稿定义**：保存的是当前**全部状态**（抬头 + 66 条勾选 + 情形 + 其他文字）。

接口：`POST /api/reports`、`PUT /api/reports/{id}`、`GET /api/reports/{id}/draft`、
`POST /api/reports/{id}/generate`、`GET /api/report/jte-items`。

### 4.6 报告详情 / 预览 `/reports/:id`

**目的**：查看生成后的报告（正文 / 评价结果表 / 附页 / 附录A），并导出。

| 区域 | 内容 |
| --- | --- |
| 顶部工具栏 | 报告编号、状态标签、生成时间、得分与等级、「返回录入」 |
| 主体 | A4 纸张等比缩放预览（**不重排**，竖屏也完整可见） |
| 悬浮岛 | 计数（只读）+ 导出 PDF + 导出 Word |

交互：

1. 进入时若 `status=draft`，提示「这份评估尚未生成，去录入页完成」并给跳转按钮。
2. 生成过程中若使用流式（`generate-stream`），正文区域逐段出现并显示「生成中…」。
3. 导出中按钮禁用；导出完成后**结果卡常驻**，含文件名、大小、路径 +
   「打开文件」「打开所在文件夹」「关闭」，并自动滚动到可见位置。
4. 导出失败给可读原因（目录不可写 / 缺少转换器）并允许重试。

接口：`GET /api/reports/{id}`、`POST /api/report/export`、`POST /api/report/open`、
`POST /api/reports/{id}/generate-stream`。

边界状态：图谱未就绪 / 模型不可用 → 明确标注（报告仍可生成，走降级）。

### 4.7 报告管理 `/reports`（新增）

**目的**：查报告、重新导出、继续编辑、作废、复制为新建。

| 区域 | 内容 |
| --- | --- |
| 筛选栏 | 关键字（编号 / 使用单位）、状态、日期区间、「只看我创建的」开关 |
| 表格列 | 报告编号、状态、使用单位、设备编号、评估日期、创建人、操作 |
| 分页 | 每页 20 条 |
| 空状态 | 「还没有报告」+ 跳录入页按钮 |

行内操作（按状态给不同项）：

| 状态 | 可用操作 |
| --- | --- |
| 草稿 | 继续编辑、删除（二次确认） |
| 已生成 | 查看、重新导出、复制为新建、作废（必填原因）、删除（二次确认） |
| 已归档 | 查看、重新导出、复制为新建、作废 |
| 已作废 | 查看（编号保留、置灰显示） |

接口：`GET /api/reports`、`POST /api/reports/{id}/void`、`POST /api/reports/{id}/clone`、
`DELETE /api/reports/{id}`。

### 4.8 账号管理 `/accounts`（新增）

**目的**：开户、停用、重置口令、看最后登录时间。

| 区域 | 内容 |
| --- | --- |
| 工具栏 | 搜索（姓名 / 用户名）、状态筛选、「新增账号」 |
| 表格列 | 姓名、用户名、工号、状态、创建时间、最后登录、报告数、操作 |
| 行内操作 | 编辑（姓名 / 工号）、停用或启用、重置口令、删除 |

交互与规则：

1. 新增 / 编辑用页面内自绘弹层表单（不用原生 prompt）。
2. **停用、删除、重置口令都要二次确认**；删除时若该账号有报告，按钮置灰并提示"改停用"。
3. **最后一个启用账号**的停用 / 删除按钮置灰，并说明原因（后端也会拒，前端提前拦）。
4. 重置口令后提示「该账号已被强制下线」。

接口：`GET/POST /api/accounts`、`PATCH/DELETE /api/accounts/{id}`、
`POST /api/accounts/{id}/reset-password`。

### 4.9 个人设置（侧栏弹层，不占路由）

1. 修改口令：原口令、新口令、确认；成功后**强制重新登录**并提示。
2. 在线会话（P1）：列出当前会话（设备/创建时间/到期时间/是否当前），可强制下线。

接口：`POST /api/auth/change-password`、`GET/DELETE /api/auth/sessions`。

### 4.10 系统设置 `/settings`（新增）

五个标签页，共用同一页面骨架：

| 标签 | 内容 | 接口 |
| --- | --- | --- |
| 基本配置 | 机构名称、报告编号前缀、导出目录、会话空闲时长、保留策略、是否允许退出系统、大模型开关。保存前展示"改了什么"，需要重启的项单独标出 | `GET/PUT /api/system/config` |
| 审计日志 | 筛选（时间 / 事件类型 / 操作者 / 结果）+ 表格 + 「导出 CSV」 | `GET /api/system/audit` |
| 备份恢复 | 「立即备份」（显示进度与产物路径）、备份列表（时间 / 大小 / 恢复）、恢复需二次确认并提示重启 | `POST /api/system/backup`、`POST /api/system/restore` |
| 诊断 | 「运行诊断」→ 检查项列表（名称 / 状态 / 原因 / 建议） | `GET /api/system/diagnose` |
| 关于 | 版本、模型名称、条目库版本与哈希、图谱规模、依赖状态、磁盘剩余 | `GET /api/system/info` |

### 4.11 列表页的通用三态

所有列表（报告 / 账号 / 日志 / 备份）必须实现三种状态，缺一不可：

1. **加载中**：骨架或「加载中…」文字，不出现空白。
2. **空数据**：一句说明 + 下一步动作按钮。
3. **出错**：可读原因 + 「重试」按钮。

## 6. 状态管理

| store | 管什么 | 变化 |
| --- | --- | --- |
| `auth` | 登录态、当前账号、`must_change_password` | 已有，扩展 |
| `setup` | 是否已初始化、是否配了恢复口令 | 新增 |
| `report` | **当前正在录入的这一份**报告（form / items / counters / 保存状态 / version） | 改造：从"每人一份全局草稿"变成"当前报告" |

原则：**只有跨页面共享的才进 store**。列表页的筛选条件、分页游标留在页面组件内，
不污染全局（否则从详情返回列表时筛选条件会被莫名重置或互相干扰）。

## 7. 与后端交互的约定（统一在 `utils/http.ts` 实现）

| 约定 | 要求 |
| --- | --- |
| **id 一律按字符串处理** | 禁止 `Number(id)`；只做等值比较与拼接（雪花 ID 超出 JS 安全整数） |
| 401 | 清登录态 → 跳登录页 → 提示「登录已过期」 |
| 403 / 409 / 422 / 503 | 直接展示后端给的 `detail`（已是可读中文）；503 额外提示"稍后重试" |
| 请求中 | 按钮禁用 + 忙碌文案；生成与导出禁止重复提交（带 `client_token`） |
| 超时 | 生成 120s、导出 60s、其它 15s；超时给可读提示，不静默失败 |
| 乐观锁 | `PUT /api/reports/{id}` 带 `version`；409 时提示「数据已被修改，请刷新」 |
| 分页 | 统一 `page` / `size`，默认 20 |
| 日期 | 只做字符串比较与展示，不做时区换算 |

## 8. 适配与交互细节

1. 两个逻辑视口：**600×960（竖）与 960×600（横）**，断点 900px。
2. 触控目标 ≥ 40×40 逻辑像素；窄屏三态按钮内边距 10px（已定稿）。
3. 不准出现横向滚动；滚动容器是 `.main`，不是 window（软键盘候选窗依赖这一点）。
4. 弹窗一律页面内自绘：WebKit 里的原生 `confirm` 会弹英文系统框**并阻塞页面**。
5. Toast 3 秒自动消失；导出结果卡**常驻**直到用户关闭。
6. 输入框聚焦时自动切中文输入法（板端），候选窗不得被软键盘遮挡。
7. 所有异步区域都要有加载 / 空 / 错误三态文案。

## 10. 验收

### 10.1 页面级（补进 `tools/acceptance/ui_acceptance.js`）

1. 每个页面：能打开、无控制台报错、无横向溢出、空状态有文案。
2. 初始化向导：口令强度拦截、两次口令不一致拦截、成功后进入系统。
3. 账号管理：最后一个启用账号的停用 / 删除被拦并给出原因。
4. 报告管理：状态标签正确；作废必须先填原因。
5. 系统设置：诊断能跑出结果；日志能按条件筛选。

### 10.2 端到端走查（扩展 `tools/acceptance/walkthrough.js`）

首次初始化 → 开户 → 录入 66 条 → 生成 → 导出 → 报告管理 → 改密 → 注销 → 忘记口令重置。
每步断言"页面非空白"（沿用现有做法）。

登录页与启动页样式、主题令牌、暖色残留、行底色规则、边框线与外框像素、
