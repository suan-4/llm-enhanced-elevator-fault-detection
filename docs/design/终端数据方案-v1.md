# 终端数据方案 v1

一体机（EM-R16 / RK3588）的数据处理、存储、备份与合规设计

| 项目 | 内容 |
|---|---|
| 版本 | v1 |
| 日期 | 2026-10-12 |
| 状态 | 待评审 |
| 适用 | 单台一体机的现场数据生命周期 |

---

## 1. 先说结论

这套系统目前能跑，但数据层面是按「单机演示」做的，直接上现场会遇到三类问题：

1. **时间不可靠**——实测硬件时钟停在 2021 年，一旦断电且无网络，报告日期就会错。
2. **数据没有退路**——业务库在系统分区里，没有自动备份，也没有迁移机制。
3. **数据出不去**——报告只能存到板子本地目录，没有归档、没有汇总、没有审计。

报告是要签字盖章的受控文件，上面三条任何一条出事，都不是技术问题，是合规问题。

## 3. 数据分三层

### 3.1 图谱数据（只读，随系统发布）

- 位置：`/var/lib/neo4j/data`，517 MB
- 内容：302 个节点、392 条关系的电梯故障演化图谱
- 变更频率：极低，只在知识库改版时更新
- 策略：**随版本发布，不随业务变化**；升级时整库替换，业务数据不在这里

### 3.2 业务数据（读写，现场产生）

- 位置：`/home/ubuntu/elevator/backend/data/elevator.db`，204 KB
- 内容：账号、会话、报告历史、填写草稿
- 变更频率：每次录入、每次生成报告都在写
- 策略：**必须备份、必须可迁移、必须能追溯**

当前它放在系统盘路径下这个位置，是最大的隐患：重刷系统或换板子时，业务数据跟着一起没。

### 3.3 导出产物（只增不减）

- 位置：`/home/user/导出/`，PDF / Word
- 单份大小：约 200 KB（PDF）、10 KB（Word）
- 变更频率：每次导出新增两个文件
- 策略：**需要保留期限与清理规则**，否则多年后会把盘写满

## 4. 六项必须补的能力

### 4.1 时间可信

**问题**：硬件时钟停在 2021-01-01。现场断电重启、又没网络时，系统时间会退回 2021 年，报告日期、报告编号、文件名时间戳全部错乱。报告是法律文件，日期错误等于报告作废。

**方案**（三层防护，缺一不可）：

1. 板子加 RTC 后备电池（硬件层，根治）。
2. 开机校时：优先 NTP，失败则从 usb0/局域网获取，再失败给出提示由人工确认。
3. **应用层兜底**：生成报告前校验年份，落在合理区间之外（如早于 2025 年）则**拒绝生成**并提示校时。不能把错误日期写进报告。

### 4.2 业务数据有退路

**方案**：

1. 业务库迁到 `/userdata`（14 G 闲置分区，系统重刷通常保留）。路径由配置项控制，不写死。
2. 每日自动备份到 `/userdata/elevator-backup/`，保留最近 N 份（建议 30 份 + 每月 1 份）。
3. 备份用 SQLite 的 `VACUUM INTO` 或 `.backup`，不用直接拷文件——直接复制正在写入的库有损坏风险。
4. 提供一键导出/导入：把整库打包成文件，供 U 盘或网络带走。

### 4.3 结构可迁移

**问题**：`user_version = 0`，`db.py` 只有 `CREATE TABLE IF NOT EXISTS`。将来加字段（比如报告编号、审计表）时，板端已存在的库不会被更新，只能手工 ALTER，现场风险极高。

**方案**：`backend/migrations/` 下放带版本号的 SQL 文件，启动时按 `user_version` 顺序执行并递增。零新依赖，二十行代码即可。任何表结构改动都必须走迁移文件，不允许手工改库。

### 4.4 容量可控

**方案**：

1. 导出目录按保留期清理（建议默认 180 天，可配置），清理前先备份。
2. 应用日志加轮转（按大小或天数），避免单文件无限增长。
3. 磁盘水位告警：可用空间低于 10% 时在界面提示。
4. 顺手回收 `rkllm` 目录里 4.6 GB 的旧模型（已停用，确认后删除）。

### 4.5 行为可追溯

**问题**：现在没有任何审计记录。谁在什么时候登录、生成、导出、删除了哪份报告，事后查不到。

**方案**：新增 `audit_log` 表，记录 `时间 / 用户 / 动作 / 对象 / 结果`，至少覆盖登录、登出、生成报告、导出报告、删除历史、用户管理。审计记录只增不改，不随历史清理而删除。

### 4.6 数据出得去

**问题**：报告只能躺在板子里，靠人退出系统去 `导出` 目录取。多台设备之间、设备与院里系统之间没有任何通道。

**待确认后再定**，见第 6 节。可选路线：

- 路线 A：**文件出板**——U 盘拷贝导出目录，最简单，零网络依赖。
- 路线 B：**局域网汇总**——板子在同一网段时，把报告与历史同步到院内服务器。
- 路线 C：**两者都要**，平时文件出板，联网时自动补传。

当前实测板子 `wlan0` 是通的，说明有网可行；但部署现场是否允许联网，需要你确认。

## 5. 数据模型改进建议

现有 4 张表结构本身是合理的（尤其「草稿只存基本信息、不存合格/不合格勾选」这个决定，避免了上一次评估结果串到下一次）。建议补充：

| 建议 | 原因 |
|---|---|
| 报告增加 `report_no`（机构统一编号/流水号） | 报告是受控文件，通常需要唯一编号；当前只有文件名时间戳 |
| 报告增加 `uuid` | 多台设备汇总时，自增 ID 会冲突，UUID 不会 |
| 报告增加 `status`（草稿 / 已生成 / 已审核 / 已批准） | 模板有评估、审核、批准三个签名栏，说明存在流程状态 |
| 报告增加 `site_id` / `device_id` | 多台设备、多个使用单位时便于归集统计 |
| 报告增加 `content_hash` | 生成后内容是否被改动，可校验 |
| 新增 `audit_log` 表 | 见 4.5 |
| 新增 `photo` 相关表 | 模板的附图页目前无数据来源 |

以上都需要你确认是否有制度要求，尤其 `report_no` 与 `status`。

## 6. 待确认问题

这些问题我无法从代码推断，需要你或业务方给结论，否则方案只能停在通用做法上。

| 编号 | 问题 | 为什么必须问清楚 |
|---|---|---|
| 1 | 现场会部署**一台**还是**一批**一体机？ | 一台不需要汇总层；一批就必须解决 ID 冲突、数据归集、版本一致 |
| 2 | 现场是**完全离线**，还是允许接入局域网/公网？ | 实测板子 `wlan0` 是通的，「完全离线」与现状不符；这决定数据出板路线 |
| 3 | 报告是否需要机构统一的**报告编号/流水号**？规则是什么？ | 影响数据模型与报告模板；当前只有文件名时间戳 |
| 4 | 报告是否需要**审核、批准流程**（模板有这三个签名栏）？ | 决定是否要做状态机与权限分级；若需要，一体机可能只承担「评估」环节 |
| 5 | 报告历史、导出文件的**保留期限**是多久？ | 决定清理策略；检验报告通常有法定保存年限 |
| 6 | 报告里的委托单位、使用单位信息，是否要求**加密或脱敏**？ | 涉及商业信息与个人信息，决定是否引入加密存储 |
| 7 | 谁有权**删除**历史记录？ | 当前任何登录用户都能删自己的记录，无审计 |
| 8 | 附图页的**现场照片**是否需要在本系统采集？ | 需要则要加拍照/上传能力与存储规划 |
| 9 | 换板、换盘、重刷系统时，业务数据由谁负责迁移？ | 决定备份机制的强度与操作手册的写法 |
| 10 | 是否需要与**院内既有系统对接**（接口或文件格式）？ | 决定汇总层的实现方式，这是最难事后补的一项 |

其中第 1、2、3、5 项影响最大，建议优先给结论。

## 7. 优先级

### P0：上现场之前必须完成

1. **时间可信**——RTC 校时 + 应用层年份校验，日期异常时拒绝生成报告。
2. **业务库迁到 `/userdata`**，并加每日自动备份。
3. **迁移机制**——`migrations/*.sql` + `user_version` 版本推进。
4. **容量治理**——导出目录保留期、日志轮转、磁盘水位告警。
5. 回收 `rkllm` 中 4.6 GB 的旧模型。

这五项都属于「不做就会在现场出事，且出事时无法挽回」。

### P1：可与一期前端并行

6. 报告编号与状态字段。
7. 审计日志表与写入点。

### P2：确认需求后再做

8. 数据汇总/同步通道（依赖第 1、2、10 项结论）。
9. 现场照片采集。
10. 敏感数据加密。

## 8. 风险清单

| 风险 | 影响 | 现状 | 对策 |
|---|---|---|---|
| 断电后时间回退到 2021 年 | 报告日期错误，文件作废 | **已存在** | RTC 电池 + 开机校时 + 应用层拦截 |
| 业务库无备份 | 数据丢失不可恢复 | **已存在** | 迁 `/userdata` + 每日 `VACUUM INTO` 备份 |
| 无迁移机制 | 表结构改动会破坏现场库 | **已存在** | 引入版本化迁移 |
| 导出目录与日志无限增长 | 多年后写满磁盘 | **已存在** | 保留期 + 轮转 + 水位告警 |
| 无审计记录 | 出问题无法追溯 | **已存在** | `audit_log` |
| 单点故障（eMMC 损坏） | 业务数据全失 | 已存在 | 备份 + 导出包 + 定期整机镜像 |
| 报告无编号 | 不符合受控文件要求 | 待确认 | 确认规则后加入模型与模板 |
| 多台设备各自为政 | 数据无法归集 | 待确认 | 预留 `uuid` / `site_id` 字段 |
